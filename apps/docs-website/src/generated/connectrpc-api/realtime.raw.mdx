Endpoint paths use the Connect convention:

`/api/connect/<fully-qualified-service>/<method>`

Use this reference when building clients against Chatto's public ConnectRPC API.


## Supporting Types

<a id="chatto-realtime-v1-RealtimeCaughtUp"></a>

### RealtimeCaughtUp

Confirms that recovery is complete and live delivery has begun.

Clients can retain `cursor` after they apply every preceding event and
resource chunk. Transient events are never replayed.

| Field | Type | Description |
| --- | --- | --- |
| `cursor` | `string` | Opaque cursor at the recovery-to-live handoff boundary. |



<a id="chatto-realtime-v1-RealtimeClientFrame"></a>

### RealtimeClientFrame

Client-to-server frame for Chatto's protobuf WebSocket realtime protocol.

Clients send binary protobuf frames to `/api/realtime`. The first frame must
be `hello`. After the server replies with `hello`, clients send
`subscribe_events` to start one authorized canonical event stream.

| Field | Type | Description |
| --- | --- | --- |
| `frame.hello` | [`RealtimeClientHello`](#chatto-realtime-v1-RealtimeClientHello) | Opens the protocol session and optionally carries a bearer token. |
| `frame.subscribe_events` | [`RealtimeSubscribeEvents`](#chatto-realtime-v1-RealtimeSubscribeEvents) | Starts the caller's authorized canonical event stream. |
| `frame.ping` | [`RealtimePing`](#chatto-realtime-v1-RealtimePing) | Application-level ping. The server replies with `pong`. |

<a id="chatto-realtime-v1-RealtimeEvent"></a>

### RealtimeEvent

One authorized canonical event.

`event` uses the same canonical shape as EVT and transient NATS Core
delivery. The server creates a fresh caller-specific value and omits events
and fields that the caller cannot see. Durable events have a resume cursor.
Transient events do not.

| Field | Type | Description |
| --- | --- | --- |
| `event` | `chatto.core.evt.v1.Event` | Authorized canonical event. The server never sends raw stored bytes. |
| `resume_cursor` | `optional string` | Opaque cursor safe to retain after this complete event is accepted. |

## Enums

<a id="chatto-core-event-v1-EventFieldSurface"></a>

### EventFieldSurface

EventFieldSurface controls whether an Event payload field can exist in
stored EVT bytes, an authorized public event, or both.

| Name | Number | Description |
| --- | --- | --- |
| `EVENT_FIELD_SURFACE_UNSPECIFIED` | `0` | The field has no explicit public surface. EVT can store it. Public projection omits it at a payload root; nested fields can inherit a classified parent message's surface. |
| `EVENT_FIELD_SURFACE_SHARED` | `1` | The field can exist in EVT and in an authorized public event. |
| `EVENT_FIELD_SURFACE_STORAGE_ONLY` | `2` | The field can exist only in EVT. Public projection removes it. |
| `EVENT_FIELD_SURFACE_CLIENT_ONLY` | `3` | The field can exist only in an authorized public event. EVT rejects it. |


<a id="chatto-realtime-v1-RealtimeInitialState"></a>

### RealtimeInitialState

Current-state behavior when a subscription cannot resume from its cursor.

| Name | Number | Description |
| --- | --- | --- |
| `REALTIME_INITIAL_STATE_UNSPECIFIED` | `0` | Invalid value. The server rejects subscriptions that use it. |
| `REALTIME_INITIAL_STATE_LIVE_ONLY` | `1` | Start at the current event boundary without sending current resources. |
| `REALTIME_INITIAL_STATE_SNAPSHOT` | `2` | Send an authorized current-state snapshot before live delivery. |


<a id="chatto-realtime-v1-RealtimeRecoveryMode"></a>

### RealtimeRecoveryMode

Recovery path selected for one subscription.

| Name | Number | Description |
| --- | --- | --- |
| `REALTIME_RECOVERY_MODE_UNSPECIFIED` | `0` | Invalid value. |
| `REALTIME_RECOVERY_MODE_LIVE_ONLY` | `1` | Delivery starts at the current boundary without a snapshot or history. |
| `REALTIME_RECOVERY_MODE_SNAPSHOT` | `2` | Resource chunks replace the client's local snapshot. |
| `REALTIME_RECOVERY_MODE_RESUME` | `3` | Current resource chunks precede durable events after the supplied cursor. |
