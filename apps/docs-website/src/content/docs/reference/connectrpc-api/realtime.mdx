Chatto exposes realtime updates at `GET /api/realtime` using binary protobuf frames from `chatto.realtime.v1`.



Read the [Realtime Protocol Overview](/guides/integrations/realtime-protocol/) before you implement the connection lifecycle, snapshot processing, event processing, targeted cursor-bounded reads, or reconnect behavior. Follow [Use Realtime From TypeScript](/guides/integrations/realtime-typescript/) for a complete browser example.



This page separates protocol frames from the public event catalogue. The [`RealtimeEvent`](#chatto-realtime-v1-RealtimeEvent) section lists every public event variant.



Realtime frames are documented separately from ConnectRPC services because they are exchanged over a long-lived WebSocket session rather than `/api/connect` RPC methods.



## Protocol Frames



These messages and enums control the WebSocket lifecycle, snapshots, recovery, liveness, errors, and closure.

<a id="chatto-realtime-v1-RealtimeSnapshot"></a>

### RealtimeSnapshot

One authorized snapshot of the current bounded server content.

The server sends at most one snapshot before `caught_up`. The client must
discard the snapshot if the socket closes before `caught_up`. List values
replace the complete local family.
Large and paginated resources, such as message history, are not part of the
snapshot and remain available through ConnectRPC.

| Field | Type | Description |
| --- | --- | --- |
| `server` | `chatto.api.v1.ServerPublicProfile` | Current public server profile. |
| `rooms` | `repeated chatto.api.v1.RoomWithViewerState` | All rooms visible to the caller at the snapshot boundary. |
| `room_groups` | `repeated chatto.api.v1.RoomGroup` | All room groups visible to the caller at the snapshot boundary. |
| `users` | `repeated chatto.api.v1.DirectoryMember` | The viewer and public users referenced by another snapshot family. |
| `active_calls` | `repeated chatto.api.v1.ActiveCall` | All active calls visible to the caller at the snapshot boundary. |

<a id="chatto-realtime-v1-RealtimeSubscribe"></a>

### RealtimeSubscribe

Starts one authorized public realtime subscription.

The client sends this message as the first binary WebSocket message. The
client does not send more application messages on the socket.

| Field | Type | Description |
| --- | --- | --- |
| `protocol_version` | `uint32` | Behavioral protocol version requested by the client. The only supported version is 4. |
| `bearer_token` | `optional string` | Optional bearer token. When present, it takes precedence over cookie auth. |
| `resume_cursor` | `optional string` | Opaque cursor from a previously received replayable event or `caught_up` frame. A usable cursor receives bounded authorized events after that position. Cursors expire 15 minutes after issue. |
| `initial_state` | [`RealtimeInitialState`](#chatto-realtime-v1-RealtimeInitialState) | Required fallback when the cursor is absent or cannot resume safely. |

### RealtimeCloseCode

Stable server-requested close category.

| Name | Number | Description |
| --- | --- | --- |
| `REALTIME_CLOSE_CODE_UNSPECIFIED` | `0` | Invalid or unknown close code. |
| `REALTIME_CLOSE_CODE_INVALID_REQUEST` | `1` | The subscription message is malformed or contains an invalid value. |
| `REALTIME_CLOSE_CODE_UNSUPPORTED_PROTOCOL` | `2` | The requested behavioral protocol version is not supported. |
| `REALTIME_CLOSE_CODE_TEMPORARILY_UNAVAILABLE` | `3` | The server cannot accept or continue a realtime session at present. |
| `REALTIME_CLOSE_CODE_AUTHENTICATION_REQUIRED` | `4` | The caller is no longer authenticated. |
| `REALTIME_CLOSE_CODE_SESSION_RENEWAL_REQUIRED` | `5` | The caller must renew its session before reconnecting. |
| `REALTIME_CLOSE_CODE_RESYNC_REQUIRED` | `6` | The client must discard its cursor and synchronize current state again. |
| `REALTIME_CLOSE_CODE_SESSION_TERMINATED` | `7` | The user's session ended and the client must return to sign-in. |
| `REALTIME_CLOSE_CODE_PRIVILEGED_MODE_EXPIRED` | `8` | Privileged mode expired. Reconnect and refresh effective viewer and room permissions. |
