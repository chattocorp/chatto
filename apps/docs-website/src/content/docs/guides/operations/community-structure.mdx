Set up the structure of your server before you invite many members. Decide on
the room layout, default access, announcement rooms, roles, and the public
identity of the server.

## First-Day Checklist

1. Set the server name, description, logo, banner, welcome message, and
   message of the day.
2. Decide which rooms all members see immediately.
3. Create room groups for the topics or teams in your community.
4. Make rooms universal when all eligible members must belong to them.
5. Create a custom role only when you need a reusable set of permissions.
6. Use room or group permissions for local behavior, not server-wide denies.
7. Keep at least one verified owner recovery email in `owners.emails`.

## Room Groups

Each channel room belongs to one room group. A group organizes the sidebar and
sets the default permissions for its rooms. Use groups for durable categories,
such as `Announcements`, `General`, `Project Teams`, or `Support`. Do not make
a group for each small topic. Room overrides are easier to understand when the
group default is correct for most rooms in the group.

A new server has a `Lobby` group with `#announcements` and `#general`.

- To add a room or link, select **+** at the end of a group header. Then
  select **New Room** (needs `room.create`) or **New Link** (needs
  `room.manage` on the group).
- To add a group, select **New Group** after the last group.
- To reorder groups, or to move rooms and links, use the drag handles.
- To change settings, archive a room, or remove an empty group, use the context
  menus.

The sidebar hides rooms that a member has not joined. The member selects
**+ N more** at the end of a group to show them, and **Show less** to hide them.

Give each discoverable room a short description. Before a member joins, the
member sees the group, the description, and a preview of the members. The
member does not see messages, files, or activity. Rooms that the member cannot
join do not show this preview.

## Universal Rooms

Make a room universal when all members who can join it must be members.
Membership comes from the room's `room.join` permission. Good candidates:

| Room | Typical policy |
| ---- | -------------- |
| `#announcements` | All members see it. Only owners and admins post. |
| `#general` | All members take part. |
| `#rules` | All members see it. Posting is restricted. |

To remove a member from a universal room, suspend the member in that room. If
you turn off **Universal**, explicit memberships from before stay.

<Aside type="tip">
  Members cannot leave a universal room. Tell members to mute noisy universal
  rooms.
</Aside>

## Explicit Room Members

Use explicit membership for private or opt-in rooms. Open
**Server Admin → Rooms**, select the room, and use its **Members** section to
add or remove members. You need `room.manage` for the room. You cannot change
members while the room is archived.

Explicit membership gives access independently of `room.list` and `room.join`.
A deny of discovery or self-join does not remove current members. Examine the
member list when you restrict a room.

## Slow Mode

Open **Server Admin → Rooms → [room] → General → Slow Mode**. Select an
interval from 5 seconds to 6 hours, or **Off**. Each member has one timer for
the room. Root messages, thread replies, and attachment-only messages all use
it.

A change applies immediately. Chatto measures from the member's last
successful post, also when that post is older than the setting. While members
wait, they can still write drafts, edit messages, and add reactions.

Members with `room.manage` or `message.manage` are exempt. Slow Mode is not
available in direct messages. It does not make a room read-only: for that,
deny `message.post`, `message.post-in-thread`, and
`message.post-in-interactions`.

## Threading Mode

Open **Server Admin → Rooms → [room] → General → Threading Mode**:

| Mode | Member experience |
| ---- | ----------------- |
| **Required** | Each new root message gets a thread. Both reply actions open the thread. The server rejects flat replies to root messages. |
| **Encouraged** | **Reply** opens the thread. **Reply in room** is in the expanded menu. **Thread** is selected for each new root draft, but members can turn it off. |
| **Enabled** | The default. Members select room replies or threads freely. |
| **Disabled** | Members cannot start threads or reply in them. Existing threads stay readable. |

A change applies to new posts only. It does not create or remove threads. The
room timeline shows who changed the mode.

Threading Mode does not replace permissions. `message.post` allows root
messages and thread replies. For reply-only access, allow
`message.post-in-thread`, or `message.post-in-interactions` to limit replies to
related threads.

## Pinned Messages

Pin messages that members need again, such as announcements, frequent answers,
or decisions.

- To pin or unpin, open the action menu of a message and select
  **Pin message** or **Unpin message**. You need `room.manage`. There is no
  separate pin permission.
- To see pins, select the pin icon in the room header. The **Pins** sidebar
  shows the full messages, newest pin first. Select a pin to open the
  original message.
- A dot on the pin icon shows a new pin since you last opened the sidebar in
  this browser.

Edits to a message show in its pin. When you delete a message, Chatto removes
its pin. Direct messages have no pins. Archived rooms keep their pins, but you
cannot change them until you unarchive the room.

## Permissions Strategy

Start with broad defaults and add local exceptions:

| Goal | Where to configure it |
| ---- | --------------------- |
| Defaults for all members | Server-scope grants on `everyone` |
| Behavior for a category of rooms | Group permissions |
| One exceptional room | Room permissions |
| One exceptional user | User permission override |
| Reusable staff capability | Custom role |

A room or group value overrides a less specific value for the same subject. A
named-role allow overrides an `everyone` deny only at the same scope or a
nearer scope. To make a deny stronger than other named grants, attach it to
the user or to a restriction role. See
[Permissions & Roles](/guides/operations/permissions/) for the full model.

## Common Structures

| Community | Structure |
| --------- | --------- |
| Small community | One `Lobby` group. Universal, read-only `#announcements`. `#general` as a normal or universal room. A `moderator` role if necessary. |
| Team or organization | One group for rooms for all members, and one group for each team or project. Universal `#announcements`. Custom roles for staff, contractors, or project leads. |
| Event or course | Universal, read-only `#announcements`. One group for each track or cohort. Sidebar links to schedules, recordings, and forms. |

## Branding And Public Presentation

Edit these fields in the admin UI:

| Field | Use |
| ----- | --- |
| Server name | The name that members recognize. Installed apps also use it. |
| Description | Link previews and server metadata. |
| Welcome message | Sign-in page notes, terms, or support links. |
| Message of the day | A short notice for signed-in members. |
| Logo | Browser tabs, installed apps, server navigation, and the sign-in page. |
| Banner | The sign-in page and link previews. |
| Blocked usernames | Names that users cannot register, such as reserved or offensive names. |

## Neighbors

<Aside type="caution">
  Neighbors is an experimental feature.
</Aside>

Neighbors is a public list of Chatto servers that you recommend to your
members. A Neighbor is a recommendation only. It is not a trust relationship,
and the other server does not have to agree.

To add a Neighbor:

1. Open **Server Configuration → Neighbors**.
2. Enter a hostname or URL, such as `chat.example.com` or a link to a room.
3. Select **Add Neighbor**.

You need `server.manage-neighbors` or `server.manage`. Chatto stores only the
origin of the URL. You can add a maximum of 100 Neighbors. You cannot add the
origin of your own server. Use **Edit** or **Delete** to change the list. The
page shows the profile of each Neighbor, so you can make sure that the server
is correct. The list has no order.

Your Chatto server does not contact the Neighbor. It does not verify that the
origin runs Chatto, is online, or approves the listing.

### Server Directory

Members select **Add Server** in the server gutter to open the Server
Directory. The directory shows the Neighbors of each server that the member
has added. It also shows Neighbors of Neighbors, for a maximum of two hops,
when the two servers recommend each other. Each result shows the servers that
recommend it. A result has a **Join** action, or **Open in new tab** when its
version is not compatible. Servers that are offline or have no valid profile
do not show.

<Aside type="note">
  The browser contacts each listed server directly. Each server can see the
  member's IP address. The directory asks the member for consent on each device
  before it makes these connections. The Neighbors administration page contacts
  the listed servers when you open it.
</Aside>

API clients can use `chatto.admin.v1.AdminServerService` to manage Neighbors
with canonical HTTP or HTTPS origins. The public
`chatto.discovery.v1.ServerDiscoveryService.ListNeighbors` method needs no
session. Older servers return `Unimplemented`.
