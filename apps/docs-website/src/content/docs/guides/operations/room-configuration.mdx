---
title: Room Configuration
description: Configure inherited room behaviour while Chatto is running.
---

Room configuration contains typed settings that change room behaviour without
a server restart. It is separate from permissions: a permission decides who
may perform an action, while configuration controls how an allowed feature
behaves.

## Inheritance

Each room setting resolves independently through these layers:

1. room
2. the room's current room group
3. server
4. Chatto's product default

Only values contributed by a layer are stored. Choose **Inherit** at any level
to remove that value and use the next layer in the chain. Parent values are
defaults, not limits: a room can select any globally valid value even when its
group or server uses another value.

Moving a room to another group immediately changes the group layer it inherits.
Direct messages have no group or room layer and inherit from the server.

## Configure Rooms

Open **Server Admin → Room configuration** to set server-wide defaults. The
same panel appears on a room group's and a room's management page for
administrators with `room.manage` there.

The panel shows both the value contributed at the current scope and the
effective value. An absent local value is shown as inherited without tracing
the exact ancestor that supplied it. Changes save immediately and are recorded
as durable events, so they are included in normal EVT backups and the
administrative event log.

## Author Edit Window

The first room setting controls how long authors may edit their own messages:

- The product default is 3 hours.
- Available administration presets range from Disabled through 7 days; the API
  accepts typed values from 0 seconds through 30 days.
- Disabled means authors cannot edit after posting.
- Users with `message.manage` can still edit messages without a time limit.
- The server evaluates the current effective value when an edit commits.
  Lowering the window can immediately close existing messages; raising it can
  make them editable again.

Compatible clients receive updated effective room configuration through the
realtime projection. During a mixed-version deployment, an older client may
briefly show an edit action based on the server-wide value, but authoritative
server enforcement still applies.

## API

Integrations can read sparse layers and update selected fields with
`chatto.admin.v1.AdminRoomConfigService`. The update field mask preserves
unselected values; omitting the value for a selected field removes it from the
layer. Normal clients receive the curated effective settings needed for client
behaviour in `chatto.api.v1.RoomViewerState`; they neither receive private
administrative settings nor need to reproduce the inheritance algorithm.
