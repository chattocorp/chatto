בוטים מאפשרים לכלים חיצוניים לפרסם הודעות ולהשיב לשיחות ב־Chatto. צור חשבון בוט, הענק לו גישה לחדרים הדרושים, וחבר את הכלי באמצעות מפתח API או webhook. את תוכנת הבוט מפעילים בנפרד.

השלבים הבאים מגדירים בוט שמפרסם עדכוני פריסה. דרושות הרשאה ליצור בוטים וגישה לחדר היעד.

## בחר איך הכלי מתחבר

יש שלוש דרכי חיבור. בוט יכול להשתמש ביותר מאחת.

- **Webhook נכנס: הכלי שלך ← Chatto.** ספק לשירות התראות או לכלי אוטומציה כתובת URL לפרסום הודעות.
- **מפתח API: התוכנית שלך ← Chatto.** תן לתוכנית הבוט מפתח כדי שתוכל לקרוא הודעות, לשלוח תשובות או לבצע פעולות API אחרות שתאפשר.
- **Webhook יוצא: Chatto ← הכלי שלך.** ספק ל־Chatto נקודת קצה לשליחת התראה כשמישהו מאזכר את הבוט או שולח לו הודעה ישירה. הכלי מטפל באירוע ומשתמש במפתח API אם עליו להשיב.

לעדכוני פריסה, השתמש ב־webhook נכנס. לבוט שמשיב לאזכורים או להודעות ישירות, השתמש ב־webhook יוצא לקבלת הודעות ובמפתח API לשליחת תשובות.

## 1. צור את חשבון הבוט

1. פתח **ניהול שרת ← בוטים** בשרת שבו הבוט יפעל.
2. בחר **צור בוט**. בדוגמה זו השתמש ב־`release-bot` כשם משתמש וב־**עדכוני גרסה** כשם תצוגה. שם המשתמש מזהה את החשבון; שם התצוגה הוא מה שחברים רואים לצד הודעותיו.
3. צור את הבוט. Chatto מציג מפתח API פעם אחת. שמור אותו במאגר הסודות של השילוב אם תשתמש ב־API. אי אפשר להציג שוב את המפתח אחרי סגירת תיבת הדו־שיח.
4. פתח את עמוד פרטי הבוט. תן לפרופיל תיאור קצר, למשל ״מפרסם תוצאות פריסה מתהליך הפצת הגרסה שלנו״.

אם **צור בוט** אינו זמין, בקש ממנהל את `bot.create`. בעלות על בוט מאפשרת לנהל את הבוט הזה; הרשאה לנהל את כל הבוטים ניתנת בנפרד.

אם הכלי משתמש רק ב־webhook נכנס, הוא אינו צריך מפתח API. בטל את המפתח הראשוני שאינו בשימוש תחת **שילובים ← מפתחות API**.

## 2. תן לו גישה לחדר אחד

לבוט חדש אין הרשאות. הוא אינו יורש את תפקידי הבעלים או את ההרשאות של התפקיד `everyone`. הצטרפות לחדר והרשאה לפרסם בו הן דרישות נפרדות.

1. פתח את הכרטיסייה **הרשאות** של הבוט.
2. מצא את העמודה של חדר עדכוני הפריסה.
3. בשורה **הצטרף** בראש המטריצה, בחר בחדר ואשר את שינוי החברות.
4. אפשר `message.post` לחדר הזה. השאר הרשאות שאינן קשורות למשימה ללא הגדרה.

בוט הפריסה אינו צריך גישת קריאה. הענק `message.post` בעמודת החדר כדי להגביל את הפרסום לחדר הזה. הרשאה ברמת השרת חלה על פני חדרים.

דרושה לך גם סמכות להוסיף את הבוט לחדר. חדרים בארכיון והשעיות בחדר עלולים למנוע הצטרפות. הרשאת הבוט עצמו `room.join` מיועדת להצטרפות לחדרים דרך ה־API שלו; היא אינה תחליף לשורה **הצטרף**.

### גישת הבוט אינה יכולה לחרוג מגישת הבעלים

כל הרשאה לבוט מוגבלת בהרשאות הנוכחיות של הבעלים האנושי באותו תחום. הרשאה שנשמרה עשויה להיות לא פעילה: מנעול במטריצה מציין שהרשאות הבעלים חוסמות אותה. אם הבעלים מאבד גישה, גם הבוט מאבד אותה. יציאה מהחשבון אינה עוצרת את הבוט.

הרשאות מסוימות דורשות מצב מיוחס. אם Chatto מבקש להפעיל אותו, עשה זאת לפני הוספת ההרשאה.

## 3. חבר webhook נכנס

1. פתח **שילובים** בעמוד פרטי הבוט.
2. תחת **Webהוקים נכנסים**, בחר **יצירת Webהוק**.
3. תן לו שם לפי הגורם הקורא, למשל **תהליך הפצת גרסה**.
4. בחר את חדר עדכוני הפריסה כ־**חדר יעד**.
5. צור את ה־webhook והעתק את כתובת ה־URL המלאה להגדרות ה־webhook של הכלי. השאר את החלק `?room_id=…` בכתובת.

הגדר את הכלי לשלוח HTTP **POST** עם `Content-Type: application/json` והגוף הבא:

```json
{
  "text": "הפריסה הושלמה: גרסה **0.5** מוכנה לבדיקה."
}
```

החדר שנבחר כבר נמצא בכתובת, ולכן הבקשה אינה צריכה שדה `channel`. אם תבחר במקום זאת **בחירה בכל בקשה**, כלול `"channel": "YOUR_ROOM_ID"` ב־JSON. השתמש במזהה החדר, לא בשמו.

בחירת יעד מוסיפה מזהה חדר לכתובת. הגורם הקורא יכול לשנות את המזהה ולפרסם בכל חדר שבו הבוט רשאי לפרסם. כדי להגביל את ה־webhook לחדר אחד, הענק לבוט הרשאת פרסום רק בחדר הזה.

## 4. שלח בדיקה ובדוק את התוצאה

השתמש בפונקציית הבדיקה של הכלי החיצוני. בקשה נכנסת מוצלחת מחזירה HTTP `200` עם הטקסט `ok`. ב־Chatto, ההודעה צריכה להופיע בחדר שנבחר בשם **עדכוני גרסה**, עם התווית **BOT** ו־״0.5״ מודגש.

אם הבקשה נכשלת, בדוק את התשובה:

- **`401 invalid_token`:** הכתובת אינה מלאה, אינה תקינה או בוטלה. צור webhook נכנס חדש אם אין לך עוד את הכתובת המלאה.
- **`404 channel_not_found`:** בדוק את מזהה החדר, חברות הבוט, הרשאת `message.post` שלו והרשאת הפרסום של הבעלים בחדר.
- **`400 invalid_payload`:** שלח JSON תקין עם טקסט הודעה שאינו ריק ומזהה חדר. אם מזהה החדר מופיע גם בכתובת וגם בגוף, הערכים חייבים להתאים. גם מדיניות החדר ומגבלות גודל ההודעות חלות.
- **ההודעה מופיעה פעמיים:** ניסיון חוזר יכול ליצור הודעה נוספת. webhooks נכנסים אינם מספקים מפתח אידמפוטנטיות למניעת כפילויות.

לאחר שהבדיקה מצליחה, הגדר את הכלי לקרוא ל־webhook כשהפריסה מסתיימת.

## צור בוט שעונה לאנשים

הגדר בתוכנית הבוט את מפתח ה־API שלו ב־Chatto. שמור את המפתח בהגדרות הסודיות של התוכנית. בקשות API מבצעות אימות באמצעות הכותרת `Authorization: Bearer YOUR_API_KEY`.

בחר את ההרשאות שהבוט צריך:

- **ענה רק כשפונים אליו:** הענק `message.read-interactions` ו־`message.post-in-interactions`. הבוט יכול לקרוא שרשורים שלמים שהתחיל, שרשורים שבהם מישהו אזכר אותו ישירות, ואת ההודעות הישירות שלו. לכן אזכור הבוט יכול לתת לו גישה גם להודעות קודמות בשרשור.
- **קרא את החדר, אך ענה רק כשפונים אליו:** הענק `message.read` ו־`message.post-in-interactions`.
- **קרא את כל ההודעות והתחל שיחות:** הענק `message.read` ו־`message.post`.

החל את ההרשאות על החדרים המיועדים. להודעות ישירות, השתמש בתחום **הודעות ישירות** במטריצה. הרשאות הבעלים עדיין מגבילות את ההרשאות האלה.

### אמור לתוכנית מתי להשיב

אם התוכנית מקבלת אירועי webhook של Chatto:

1. פתח **שילובים ← Webhooks יוצאים ← יצירת webhook**.
2. הזן שם ואת נקודת הקצה הציבורית ב־HTTPS של התוכנית.
3. אם המקבל דורש **כותרת Authorization**, הזן את הערך המלא שהוא מצפה לו, כולל קידומת כגון `Bearer`.
4. העתק את סוד החתימה להגדרות המקבל אם הוא מאמת חתימות webhook של Chatto. הסוד מוצג פעם אחת בלבד.
5. אזכר את הבוט בחדר שהוא יכול לקרוא, או שלח לו הודעה ישירה. בדוק את יומני המקבל ואת תשובת הבוט ב־Chatto.

נקודת הקצה מקבלת הודעות חדשות שמאזכרות את הבוט ישירות או נמצאות בהודעות הישירות שלו. הודעות רגילות בחדר, עריכות, תגובות והודעות שהבוט עצמו שולח אינן מפעילות webhooks אלה. גם תשובה רגילה מאוחרת יותר בשרשור חדר אינה מפעילה אותם, אלא אם היא מאזכרת שוב את הבוט.

המקבל צריך לקבל את האירוע בתשובת HTTP 2xx, ואז לשלוח כל תשובה לצ'אט דרך ה־API. Chatto מתעלם מגוף תשובת HTTP. מסירות עלולות לחזור, ולכן המקבל חייב להשתמש במזהה המסירה כדי לא לבצע אותה עבודה פעמיים. לתוכנית שצריכה את כל הפעילות שניתן לקרוא, השתמש ב־API זמן אמת של Chatto במקום ב־webhook של אזכורים והודעות ישירות.

למבנה נתוני האירוע, אימות החתימה ופעולות ה־API, השתמש ב־[מדריך ה־webhooks לבוטים](https://docs.chatto.run/reference/bot-webhooks/) וב־[מדריך ה־API](https://docs.chatto.run/reference/connectrpc-api/).

webhook יוצא שולח את טקסט ההודעה ואת מזהי ההודעה, הכותב, החדר והבוט לנקודת הקצה שהוגדרה. המקבל רואה גם את כתובת ה־IP היוצאת של שרת Chatto. אם הבוט מעביר הודעות לספק בינה מלאכותית או לשירות אחר, הסבר זאת לחברים לפני השימוש בו בשיחות שלהם.

### אם הבוט שותק

בדוק אם התוכנית קיבלה את האירוע. תחת ה־webhook היוצא, פתח **כשלים אחרונים** כדי לראות שגיאות מסירה שתועדו. בדוק שנקודת הקצה מופעלת, נגישה, מקבלת את האימות שהוגדר ומחזירה 2xx ללא הפניה. רשימת כשלים ריקה אינה מוכיחה שהמסירה הצליחה.

אם האירוע הגיע אך לא הופיעה תשובה, בדוק את מפתח ה־API של התוכנית, את פעולת התשובה ואת הרשאות הקריאה והפרסום האפקטיביות של הבוט.

## תחזק את השילוב

- **החלפת פרטי גישה:** צור מפתח או webhook חדש בעל שם, עדכן את הגורם הקורא, בדוק אותו ואז בטל את הישן. מפתחות API אינם פוקעים אוטומטית. לעולם אל תדביק מפתח אמיתי או כתובת שמכילה פרטי גישה בצ'אט או במערכת ניהול קוד.
- **עצירת מסירה יוצאת זמנית:** בחר **השהיה** בנקודת הקצה. **המשך** מאפשר אירועים חדשים; הוא אינו משחזר את תקופת ההשהיה.
- **העברת הבוט לבעלים אחר:** חשבון עם `bot.manage` יכול להשתמש ב־**הקצאת בעלים מחדש**. הגישה האפקטיבית של הבוט משתנה מיד לפי הבעלים החדש. מפתחות קיימים נשארים תקפים, ולכן החלף פרטי גישה אם המפעיל הקודם צריך לאבד גישה.
- **מחיקת חשבון בעלים:** הקצה תחילה בעלים חדשים לבוטים שצריכים להמשיך לפעול. מחיקת בעלים אנושי מוחקת גם את הבוטים שבבעלותו.
- **הצגת יכולות הבוט לחברים:** פתח את הפרופיל ובדוק את **בבעלות** ואת **מה הוא יכול לעשות**. בדוק את הגישה אחרי שינוי חדרים או בעלות.
