## PushNotificationService

Browser Web Push subscription commands. Account mutations authenticate the
current user; late-save cleanup uses the exact subscription's capability.

<a id="chatto-api-v1-PushNotificationService-Subscribe"></a>

### Subscribe

Stores or updates the caller's browser push subscription.

The server must have Web Push configured. Clients normally call this after
the browser grants notification permission and returns a PushSubscription.

```http
POST /api/connect/chatto.api.v1.PushNotificationService/Subscribe
```

<a id="chatto-api-v1-SubscribePushRequest"></a>

#### Input: SubscribePushRequest

Request to store a PushSubscription returned by the browser Push API.

| Field | Type | Description |
| --- | --- | --- |
| `endpoint` | `string` | Absolute HTTPS push service endpoint URL. The server rejects redirects and destinations that resolve to private or other special-use addresses. |
| `p256dh` | `string` | Client P-256 ECDH public key from PushSubscription.keys.p256dh. |
| `auth` | `string` | Authentication secret from PushSubscription.keys.auth. |
| `user_agent` | `optional string` | Optional browser user-agent string for device identification. |
| `client_host` | `optional string` | URL host of the Chatto server that supplied the installed web app. The sending server combines this with its own hostname to reconstruct the client route. A host can include a port but no scheme, path, or user info. SubscribeForClient requires this field; Subscribe ignores it. |


<a id="chatto-api-v1-SubscribePushResponse"></a>

#### Result: SubscribePushResponse

Response from storing a browser push subscription.

| Field | Type | Description |
| --- | --- | --- |
| `subscribed` | `bool` | True when the subscription was stored. |


<a id="chatto-api-v1-PushNotificationService-SubscribeForClient"></a>

### SubscribeForClient

Stores a subscription whose notifications must open a different Chatto
server's installed web app. This separate RPC makes rolling upgrades fail
closed: older replicas reject the unknown method before storing anything.

```http
POST /api/connect/chatto.api.v1.PushNotificationService/SubscribeForClient
```

Uses the same input shape documented above.

#### Result: [SubscribePushResponse](#chatto-api-v1-SubscribePushResponse)

Uses the same result shape documented above.

<a id="chatto-api-v1-PushNotificationService-Unsubscribe"></a>

### Unsubscribe

Removes the caller's browser push subscription by endpoint.

The call is idempotent: removing an unknown endpoint still succeeds.

```http
POST /api/connect/chatto.api.v1.PushNotificationService/Unsubscribe
```

<a id="chatto-api-v1-PushNotificationService-DeleteSubscriptionByCapability"></a>

### DeleteSubscriptionByCapability

Removes the exact current subscription when its Push API auth secret
matches. This capability-based cleanup does not use the current account's
session, allowing cancelled registration to finish safely after sign-out.

```http
POST /api/connect/chatto.api.v1.PushNotificationService/DeleteSubscriptionByCapability
```

<a id="chatto-api-v1-DeletePushSubscriptionByCapabilityRequest"></a>

#### Input: DeletePushSubscriptionByCapabilityRequest

Capability-authenticated request to remove an exact push subscription.

| Field | Type | Description |
| --- | --- | --- |
| `endpoint` | `string` | Push service endpoint URL identifying the current endpoint owner. |
| `auth` | `string` | Authentication secret from the same browser PushSubscription. Cleanup is a no-op unless it matches the exact current subscription revision. |


<a id="chatto-api-v1-DeletePushSubscriptionByCapabilityResponse"></a>

#### Result: DeletePushSubscriptionByCapabilityResponse

Response from capability-authenticated subscription cleanup.

| Field | Type | Description |
| --- | --- | --- |
| `completed` | `bool` | True when the idempotent cleanup request completed. It does not reveal whether a matching subscription existed. |


<a id="chatto-api-v1-PushNotificationService-SendTestNotification"></a>

### SendTestNotification

Sends a test notification to the caller's registered browser subscriptions.
Calls are rate-limited per account. Delivery failures return a generic
unavailable error without exposing the push provider's response body.

```http
POST /api/connect/chatto.api.v1.PushNotificationService/SendTestNotification
```

<a id="chatto-api-v1-SendTestPushNotificationRequest"></a>

#### Input: SendTestPushNotificationRequest

Request to test the current user's registered browser push subscriptions.


<a id="chatto-api-v1-SendTestPushNotificationResponse"></a>

#### Result: SendTestPushNotificationResponse

Result of sending a test Web Push notification.

| Field | Type | Description |
| --- | --- | --- |
| `sent` | `bool` | True when the push provider accepted the notification. |
