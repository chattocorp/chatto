تتيح البوتات للأدوات الخارجية نشر الرسائل والرد على المحادثات في Chatto. أنشئ حساب بوت، وامنحه الوصول إلى الغرف التي يحتاج إليها، ثم اربط أداتك بمفتاح API أو webhook. تشغّل برنامج البوت بصورة مستقلة.

تُعدّ الخطوات التالية بوتًا ينشر تحديثات النشر. تحتاج إلى إذن إنشاء البوتات والوصول إلى الغرفة المستهدفة.

## اختر طريقة اتصال أداتك

توجد ثلاث طرق للاتصال. يمكن للبوت استخدام أكثر من واحدة.

- **Webhook وارد: أداتك ← Chatto.** امنح خدمة تنبيه أو أداة أتمتة عنوان URL لنشر الرسائل إليه.
- **مفتاح API: برنامجك ← Chatto.** امنح برنامج البوت مفتاحًا ليقرأ الرسائل ويرسل الردود أو ينفّذ عمليات API الأخرى التي تسمح بها.
- **Webhook صادر: Chatto ← أداتك.** أعطِ Chatto نقطة نهاية لإشعارها عندما يشير شخص إلى البوت أو يرسل إليه رسالة مباشرة. تعالج أداتك الحدث وتستخدم مفتاح API إذا احتاجت إلى الرد.

لتحديثات النشر، استخدم webhook واردًا. للبوت الذي يجيب عن الإشارات أو الرسائل المباشرة، استخدم webhook صادرًا لتلقي الرسائل ومفتاح API لإرسال الردود.

## 1. أنشئ حساب البوت

1. افتح **إدارة الخادم ← الروبوتات** على الخادم الذي سيعمل عليه البوت.
2. اختر **إنشاء بوت**. استخدم في هذا المثال `release-bot` اسمًا للمستخدم و**تحديثات الإصدار** اسمًا للعرض. يعرّف اسم المستخدم الحساب؛ واسم العرض هو ما يراه الأعضاء بجوار رسائله.
3. أنشئ البوت. يعرض Chatto مفتاح API مرة واحدة. احفظه في مخزن أسرار التكامل إذا كنت ستستخدم API. لا يمكنك إظهار هذا المفتاح مجددًا بعد إغلاق مربع الحوار.
4. افتح صفحة تفاصيل البوت. أضف وصفًا قصيرًا إلى ملفه الشخصي، مثل «ينشر نتائج النشر من مسار الإصدار لدينا».

إذا لم يتوفر **إنشاء بوت**، فاطلب `bot.create` من المسؤول. امتلاك بوت يتيح لك إدارته؛ أما إذن إدارة جميع البوتات فيُمنح بشكل مستقل.

إذا كانت أداتك تستخدم webhook واردًا فقط، فلا تحتاج إلى مفتاح API. ألغِ المفتاح الأولي غير المستخدم ضمن **التكاملات ← مفاتيح API**.

## 2. امنحه الوصول إلى غرفة واحدة

لا يملك البوت الجديد أي أذونات. ولا يرث أدوار مالكه أو أذونات دور `everyone`. الانضمام إلى غرفة والسماح بالنشر فيها شرطان منفصلان.

1. افتح علامة تبويب **الأذونات** للبوت.
2. ابحث عن عمود غرفة تحديثات النشر.
3. في صف **تم الانضمام** أعلى المصفوفة، اختر تلك الغرفة وأكّد تغيير العضوية.
4. اسمح بـ `message.post` لتلك الغرفة. اترك الأذونات غير المتعلقة بالمهمة دون ضبط.

لا يحتاج بوت النشر إلى صلاحية القراءة. امنح `message.post` في عمود الغرفة لحصر النشر فيها. الإذن على مستوى الخادم ينطبق عبر الغرف.

تحتاج أيضًا إلى صلاحية إضافة البوت إلى الغرفة. قد تمنع الغرف المؤرشفة أو حالات الإيقاف في الغرفة الانضمام. إذن البوت نفسه `room.join` مخصص للانضمام عبر API، وليس بديلًا لصف **تم الانضمام**.

### لا يمكن أن يتجاوز وصول البوت وصول مالكه

كل إذن للبوت محدود بالأذونات الحالية لمالكه البشري في النطاق نفسه. قد يكون الإذن المحفوظ غير نشط: يشير القفل في المصفوفة إلى أن أذونات المالك تمنعه. إذا فقد المالك الوصول، فقد البوت ذلك الوصول أيضًا. تسجيل الخروج لا يوقف البوت.

تتطلب بعض الأذونات وضع الامتيازات. إذا طلب Chatto تفعيله، فافعل ذلك قبل إضافة الإذن.

## 3. اربط webhook واردًا

1. افتح **التكاملات** في صفحة تفاصيل البوت.
2. ضمن **خطافات الويب الواردة**، اختر **إنشاء خطاف ويب**.
3. سمّه باسم الجهة المستدعية، مثل **مسار الإصدار**.
4. اختر غرفة تحديثات النشر بوصفها **غرفة الوجهة**.
5. أنشئ webhook وانسخ عنوان URL الكامل إلى إعداد webhook في أداتك. احتفظ بجزء `?room_id=…` من العنوان.

اضبط الأداة لإرسال HTTP **POST** مع `Content-Type: application/json` وهذا الجسم:

```json
{
  "text": "اكتمل النشر: الإصدار **0.5** جاهز للاختبار."
}
```

الغرفة المحددة موجودة في URL، لذلك لا يحتاج هذا الطلب إلى حقل `channel`. إذا اخترت **الاختيار في كل طلب** بدلًا من ذلك، فأضف `"channel": "YOUR_ROOM_ID"` إلى JSON. استخدم معرّف الغرفة، لا اسمها.

يضيف اختيار الوجهة معرّف غرفة إلى URL. يمكن للجهة المستدعية تغيير المعرّف والنشر في أي غرفة يستطيع البوت النشر فيها. لحصر webhook في غرفة واحدة، امنح البوت إذن النشر في تلك الغرفة فقط.

## 4. أرسل اختبارًا وتحقّق من النتيجة

استخدم وظيفة الاختبار في الأداة الخارجية. يعيد الطلب الوارد الناجح HTTP `200` مع النص `ok`. يجب أن تظهر الرسالة في Chatto داخل الغرفة المختارة باسم **تحديثات الإصدار**، مع علامة **BOT** و«0.5» بخط غامق.

إذا فشل الطلب، فتحقّق من الاستجابة:

- **`401 invalid_token`:** العنوان ناقص أو غير صالح أو ملغى. أنشئ webhook واردًا جديدًا إذا لم تعد تملك العنوان الكامل.
- **`404 channel_not_found`:** تحقّق من معرّف الغرفة وعضوية البوت وإذنه `message.post` وصلاحية المالك للنشر في تلك الغرفة.
- **`400 invalid_payload`:** أرسل JSON صالحًا يحتوي نص رسالة غير فارغ ومعرّف غرفة. إذا ظهر المعرّف في URL والجسم معًا، فيجب أن تتطابق القيمتان. تنطبق أيضًا سياسة الغرفة وحدود حجم الرسائل.
- **تظهر الرسالة مرتين:** قد تنشئ إعادة المحاولة رسالة أخرى. لا توفر webhooks الواردة مفتاحًا لضمان عدم تكرار العملية ومنع النسخ المكررة.

بعد نجاح الاختبار، اضبط الأداة لاستدعاء webhook عند اكتمال النشر.

## أنشئ بوتًا يجيب الناس

اضبط برنامج البوت بمفتاح Chatto API الخاص به. خزّن المفتاح في إعدادات البرنامج السرية. تستخدم طلبات API الترويسة `Authorization: Bearer YOUR_API_KEY` للمصادقة.

اختر الأذونات التي يحتاج إليها البوت:

- **الرد عند مخاطبته فقط:** امنح `message.read-interactions` و`message.post-in-interactions`. يمكن للبوت قراءة السلاسل الكاملة التي بدأها، والسلاسل التي أُشير إليه فيها مباشرةً، ورسائله المباشرة. لذلك قد تمنحه الإشارة إليه الوصول إلى رسائل أقدم في السلسلة أيضًا.
- **قراءة الغرفة، لكن الرد عند مخاطبته فقط:** امنح `message.read` و`message.post-in-interactions`.
- **قراءة جميع الرسائل وبدء المحادثات:** امنح `message.read` و`message.post`.

طبّق الأذونات على الغرف المقصودة. للرسائل المباشرة، استخدم نطاق **الرسائل المباشرة** في المصفوفة. ما زالت أذونات المالك تحدّ هذه الأذونات.

### أخبر برنامجك بموعد الرد

إذا كان برنامجك يقبل أحداث webhook من Chatto:

1. افتح **التكاملات ← خطافات الويب الصادرة ← إنشاء خطاف ويب**.
2. أدخل اسمًا ونقطة نهاية HTTPS العامة لبرنامجك.
3. إذا احتاج المستقبِل إلى **ترويسة Authorization**، فأدخل القيمة الكاملة التي يتوقعها، بما فيها بادئة مثل `Bearer`.
4. انسخ سر التوقيع إلى إعدادات المستقبِل إذا كان يتحقق من توقيعات webhooks الخاصة بـ Chatto. يظهر السر مرة واحدة فقط.
5. أشِر إلى البوت في غرفة يستطيع قراءتها، أو أرسل إليه رسالة مباشرة. راجع سجلات المستقبِل ورد البوت في Chatto.

تتلقى نقطة النهاية الرسائل الجديدة التي تشير إلى البوت مباشرةً أو تكون ضمن رسائله المباشرة. لا تشغّل رسائل الغرف العادية أو التعديلات أو التفاعلات أو الرسائل التي يرسلها البوت نفسه هذه webhooks. ولا يشغّلها رد عادي لاحق في سلسلة غرفة ما لم يُشِر إلى البوت مجددًا.

يجب أن يقبل المستقبِل الحدث باستجابة HTTP 2xx، ثم يرسل أي رد إلى الدردشة عبر API. يتجاهل Chatto جسم استجابة HTTP. قد تتكرر عمليات التسليم، لذا يجب أن يستخدم المستقبِل معرّف التسليم لتجنب تنفيذ العمل نفسه مرتين. للبرنامج الذي يحتاج جميع الأنشطة القابلة للقراءة، استخدم API الوقت الفعلي في Chatto بدل webhook الإشارات والرسائل المباشرة.

لمعرفة حمولة الحدث والتحقق من التوقيع وعمليات API، استخدم [مرجع webhooks للبوتات](https://docs.chatto.run/reference/bot-webhooks/) و[مرجع API](https://docs.chatto.run/reference/connectrpc-api/).

يرسل webhook الصادر نص الرسالة ومعرّفات الرسالة والكاتب والغرفة والبوت إلى نقطة النهاية المضبوطة. يرى المستقبِل أيضًا عنوان IP الصادر لخادم Chatto. إذا كان بوتك يعيد توجيه الرسائل إلى مزوّد ذكاء اصطناعي أو خدمة أخرى، فاشرح ذلك للأعضاء قبل استخدامه في محادثاتهم.

### إذا بقي البوت صامتًا

تحقّق مما إذا كان برنامجك تلقى الحدث. ضمن webhook الصادر، افتح **الإخفاقات الأخيرة** لعرض أخطاء التسليم المسجلة. تأكد أن نقطة النهاية مفعّلة ويمكن الوصول إليها وتقبل المصادقة المضبوطة وتعيد 2xx دون إعادة توجيه. خلو قائمة الإخفاقات لا يثبت نجاح التسليم.

إذا وصل الحدث ولم يظهر رد، فتحقّق من مفتاح API للبرنامج وعملية الرد والأذونات الفعلية للبوت للقراءة والنشر.

## حافظ على التكامل

- **استبدال بيانات اعتماد:** أنشئ مفتاحًا أو webhook جديدًا باسم، وحدّث الجهة المستدعية، واختبره، ثم ألغِ القديم. لا تنتهي صلاحية مفاتيح API تلقائيًا. لا تلصق أبدًا مفتاحًا حقيقيًا أو عنوان URL يحتوي بيانات اعتماد في الدردشة أو نظام إدارة الشيفرة.
- **إيقاف التسليم الصادر مؤقتًا:** اختر **إيقاف مؤقت** على نقطة النهاية. يسمح **استئناف** بأحداث جديدة، ولا يعيد تشغيل أحداث فترة الإيقاف.
- **تسليم البوت إلى مالك آخر:** يستطيع حساب لديه `bot.manage` استخدام **إعادة تعيين المالك**. يتبع الوصول الفعلي للبوت المالك الجديد فورًا. تبقى المفاتيح الحالية صالحة، لذا استبدل بيانات الاعتماد إذا كان يجب أن يفقد المشغّل السابق الوصول.
- **حذف حساب مالك:** أعد تعيين البوتات طويلة الأمد أولًا. حذف المالك البشري يحذف أيضًا البوتات التي يملكها.
- **عرض قدرات البوت للأعضاء:** افتح ملفه الشخصي وافحص **يملكه** و**ما يمكنه فعله**. راجع هذا الوصول بعد تغيير الغرف أو الملكية.
