Chatto exposes realtime updates at `GET /api/realtime` using binary protobuf frames from `chatto.realtime.v1`.

Read the [Realtime Protocol Overview](/guides/integrations/realtime-protocol/) before you implement the connection lifecycle, projection reducer, room hydration, or reconnect behavior. Follow [Use Realtime From TypeScript](/guides/integrations/realtime-typescript/) for a complete browser example.

This page is the field-level reference. Realtime frames are documented separately from ConnectRPC services because they are exchanged over a long-lived WebSocket session rather than `/api/connect` RPC methods.

<a id="chatto-realtime-v1-RealtimeClientFrame"></a>

### RealtimeClientFrame

Client-to-server frame for Chatto's protobuf WebSocket realtime protocol.

Clients send binary protobuf frames to `/api/realtime`. The first frame must
be `hello`. After the server replies with `hello`, clients send
`subscribe_events` to start one authorized semantic event stream.

| Field                    | Type                                                                     | Description                                                       |
| ------------------------ | ------------------------------------------------------------------------ | ----------------------------------------------------------------- |
| `frame.hello`            | [`RealtimeClientHello`](#chatto-realtime-v1-RealtimeClientHello)         | Opens the protocol session and optionally carries a bearer token. |
| `frame.subscribe_events` | [`RealtimeSubscribeEvents`](#chatto-realtime-v1-RealtimeSubscribeEvents) | Starts the caller's authorized semantic event stream.             |
| `frame.ping`             | [`RealtimePing`](#chatto-realtime-v1-RealtimePing)                       | Application-level ping. The server replies with `pong`.           |
| `frame.hydrate_room`     | [`RealtimeHydrateRoom`](#chatto-realtime-v1-RealtimeHydrateRoom)         | Requests current state for one joined room's recent timeline.     |

metadata and the cursor stay outside the event `oneof`, so a client can
