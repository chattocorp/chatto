機器人讓外部工具能在 Chatto 中發佈訊息和回覆對話。建立機器人帳號，授予它存取所需聊天室的權限，再透過 API 金鑰或 webhook 連接你的工具。機器人軟體需要另外執行。

以下步驟將設定一個發佈部署更新的機器人。你需要建立機器人的權限，並能存取目標聊天室。

## 選擇工具的連線方式

有三種連線方式。一個機器人可以同時使用多種方式。

- **傳入 webhook：你的工具 → Chatto。**為警示服務或自動化工具提供一個用來發佈訊息的 URL。
- **API 金鑰：你的程式 → Chatto。**給自己的機器人程式一把金鑰，讓它讀取訊息、傳送回覆或執行你允許的其他 API 操作。
- **傳出 webhook：Chatto → 你的工具。**向 Chatto 提供端點，以便在有人提及機器人或向它傳送私人訊息時通知該端點。你的工具處理事件，需要回覆時使用 API 金鑰。

發佈部署更新時，使用傳入 webhook。若要讓機器人回覆提及或私人訊息，使用傳出 webhook 接收訊息，使用 API 金鑰傳送回覆。

## 1. 建立機器人帳號

1. 在機器人將運作的伺服器上開啟**伺服器管理 → 機器人**。
2. 選擇**創建機器人**。本例使用 `release-bot` 作為使用者名稱，**發佈更新**作為顯示名稱。使用者名稱用來識別帳號；顯示名稱是成員在訊息旁看到的名稱。
3. 建立機器人。Chatto 只顯示一次 API 金鑰。如果要使用 API，請將金鑰儲存至整合的機密儲存空間。關閉對話方塊後無法再次查看該金鑰。
4. 開啟機器人的詳細資料頁面。在個人資料中填寫簡短說明，例如「發佈來自發佈管線的部署結果」。

如果無法使用**創建機器人**，請向管理員申請 `bot.create` 權限。擁有機器人表示可以管理該機器人；管理所有機器人的權限需要另外授予。

如果工具僅使用傳入 webhook，就不需要 API 金鑰。請在**整合 → API 金鑰**中撤銷未使用的初始金鑰。

## 2. 授予一個聊天室的存取權限

新機器人沒有任何權限。它不會繼承擁有者的角色，也不會繼承 `everyone` 角色的權限。加入聊天室和有權在該聊天室發佈訊息是兩個獨立要求。

1. 開啟機器人的**權限**分頁。
2. 找到部署更新聊天室對應的欄。
3. 在矩陣頂端的**已加入**列中選擇該聊天室，並確認成員資格變更。
4. 為該聊天室允許 `message.post`。不相關的權限保持未設定。

部署機器人不需要讀取權限。在聊天室欄中授予 `message.post`，可將發佈範圍限制在該聊天室。伺服器層級的授權會跨聊天室生效。

你也需要有權將機器人加入聊天室。已封存聊天室和聊天室停權可能阻止加入。機器人自己的 `room.join` 權限用於透過 API 加入聊天室，不能取代**已加入**列。

### 機器人的權限不能超出擁有者的權限

每項機器人授權都受人類擁有者在相同範圍內的目前權限限制。已儲存的授權可能尚未生效：矩陣中的鎖表示擁有者的權限阻止了該授權。如果擁有者失去存取權，機器人也會失去相同權限。登出不會停止機器人。

某些授權需要特權模式。如果 Chatto 要求啟用該模式，請先啟用，再加入授權。

## 3. 連接傳入 webhook

1. 在機器人的詳細資料頁面開啟**整合**。
2. 在**傳入 Webhook**下選擇**建立 Webhook**。
3. 以呼叫端命名，例如**發佈管線**。
4. 將部署更新聊天室選為**目標聊天室**。
5. 建立 webhook，將完整 URL 複製到工具的 webhook 設定中。保留 URL 中的 `?room_id=…` 部分。

設定工具傳送 HTTP **POST**，使用 `Content-Type: application/json` 和以下本文：

```json
{
  "text": "部署完成：版本 **0.5** 已可測試。"
}
```

選定的聊天室已包含在 URL 中，因此此請求不需要 `channel` 欄位。如果改選**在每個請求中選擇**，請在 JSON 中包含 `"channel": "YOUR_ROOM_ID"`。使用聊天室 ID，而非名稱。

選擇目標只是在 URL 中加入聊天室 ID。呼叫端可以修改該 ID，向機器人有權發佈的任何聊天室發佈訊息。若要將 webhook 限制在一個聊天室，請只授予機器人在該聊天室發佈的權限。

## 4. 傳送測試並檢查結果

使用外部工具的測試功能。成功的傳入請求會回傳 HTTP `200` 和文字 `ok`。在 Chatto 中，訊息應出現在選定的聊天室裡，傳送者為**發佈更新**，帶有 **BOT** 標籤，且「0.5」為粗體。

如果請求失敗，請檢查回應：

- **`401 invalid_token`：**URL 不完整、無效或已撤銷。如果不再持有完整 URL，請建立新的傳入 webhook。
- **`404 channel_not_found`：**檢查聊天室 ID、機器人的成員資格、其 `message.post` 授權，以及擁有者在該聊天室的發佈權限。
- **`400 invalid_payload`：**傳送有效 JSON，包含非空訊息文字和聊天室 ID。如果 URL 和本文中都有聊天室 ID，兩者必須一致。聊天室政策和訊息大小限制仍然適用。
- **訊息出現兩次：**重試可能建立另一則訊息。傳入 webhook 不提供用來避免重複的冪等金鑰。

測試成功後，設定工具在部署完成時呼叫 webhook。

## 建立會回覆人的機器人

為機器人程式設定它的 Chatto API 金鑰。將金鑰儲存在程式的機密設定中。API 請求透過 `Authorization: Bearer YOUR_API_KEY` 標頭進行驗證。

選擇機器人所需的權限：

- **僅在被點名時回覆：**授予 `message.read-interactions` 和 `message.post-in-interactions`。機器人可以讀取它發起的完整討論串、有人直接提及它的討論串，以及它的私人訊息。因此，提及機器人也可能讓它取得該討論串中較早訊息的存取權。
- **讀取聊天室，但僅在被點名時回覆：**授予 `message.read` 和 `message.post-in-interactions`。
- **讀取全部訊息並發起對話：**授予 `message.read` 和 `message.post`。

將授權套用至目標聊天室。私人訊息使用矩陣中的**私訊**範圍。擁有者的權限仍然限制這些授權。

### 告訴程式何時應該回覆

如果你的程式接收 Chatto webhook 事件：

1. 開啟**整合 → 傳出 Webhook → 建立 Webhook**。
2. 輸入名稱和程式的公開 HTTPS 端點。
3. 如果接收端要求 **Authorization 標頭**，請輸入它預期的完整值，包括 `Bearer` 之類的前綴。
4. 如果接收端驗證 Chatto webhook 簽章，請將簽章密鑰複製到其設定中。該密鑰只顯示一次。
5. 在機器人可讀取的聊天室中提及它，或向它傳送私人訊息。檢查接收端記錄及機器人在 Chatto 中的回覆。

端點會接收直接提及機器人或屬於其私人訊息的新訊息。一般聊天室訊息、編輯、反應及機器人自己傳送的訊息不會觸發這些 webhook。聊天室討論串中後續的一般回覆也不會觸發，除非再次提及機器人。

接收端應以 HTTP 2xx 回應接受事件，再透過 API 傳送聊天回覆。Chatto 會忽略 HTTP 回應本文。傳遞可能重複，因此接收端必須使用傳遞 ID，避免重複處理。如果程式需要所有可讀取的活動，請使用 Chatto 即時 API，而非僅處理提及和私人訊息的 webhook。

事件資料、簽章驗證和 API 操作請參閱[機器人 webhook 參考](https://docs.chatto.run/reference/bot-webhooks/)及 [API 參考](https://docs.chatto.run/reference/connectrpc-api/)。

傳出 webhook 會將訊息文字以及訊息、作者、聊天室和機器人的識別碼傳送至設定的端點。接收端也能看到 Chatto 伺服器的對外 IP 位址。如果機器人會將訊息轉送給 AI 供應商或其他服務，請在將它用於成員對話之前向成員說明。

### 如果機器人沒有回覆

檢查程式是否收到事件。在傳出 webhook 下開啟**最近的失敗**，查看記錄的傳遞錯誤。檢查端點是否啟用、可存取、接受已設定的驗證，並回傳不含重新導向的 2xx 回應。失敗清單為空並不能證明傳遞成功。

如果事件已到達但沒有回覆，請檢查程式的 API 金鑰、回覆操作，以及機器人的有效讀取和發佈權限。

## 維護整合

- **更換憑證：**建立新的具名金鑰或 webhook，更新呼叫端，測試後撤銷舊憑證。API 金鑰不會自動到期。切勿將真實金鑰或含憑證的 URL 貼到聊天或版本控制系統中。
- **暫時停止傳出傳遞：**在端點上選擇**暫停**。**恢復**允許接收新事件，但不會重播暫停期間的事件。
- **將機器人交給另一位擁有者：**具有 `bot.manage` 權限的帳號可以使用**重新指派擁有者**。機器人的有效權限會立即跟隨新擁有者。現有金鑰仍有效；如果原操作者必須失去存取權，請更換憑證。
- **刪除擁有者帳號：**先重新指派需要長期運作的機器人。刪除人類擁有者也會刪除其擁有的機器人。
- **向成員展示機器人的能力：**開啟機器人資料，查看**擁有者**及**它能做什麼**。變更聊天室或擁有權後，請重新檢查權限。
