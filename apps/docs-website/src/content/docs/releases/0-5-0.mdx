## Using Chatto

<ReleaseFeatureGrid>
  <ReleaseFeatureCard title="Bots" size="large">
    Create [bot accounts](/guides/integrations/bot-accounts/) that post, reply, and react through the same API as
    members. Each bot has an owner, its own permissions, and up to 20 named API
    keys. A bot never gets more access than its owner.
  </ReleaseFeatureCard>

  <ReleaseFeatureCard title="Search across your server" size="large">
    [Find messages](/guides/operations/search/#search-messages) in every room you can read, including threads and direct
    messages. Filter by room, author, date, or attachments. Type `?` in the
    Cmd-K finder to search all your servers at once.
  </ReleaseFeatureCard>

  <ReleaseFeatureCard title="Notifications that stay" size="large">
    Notifications now stay in one list after you read them, until you delete
    them. [Choose how each kind of activity reaches you](/guides/operations/notifications-web-push/#notification-policy),
    per server, room group, or room.
  </ReleaseFeatureCard>

  <ReleaseFeatureCard title="A new composer" size="large">
    Write in Markdown or in the new [Visual editor](/getting-started/message-formatting/), with a formatting toolbar and
    keyboard shortcuts. Insert timestamps that every reader sees in their own
    time zone, and write tables.
  </ReleaseFeatureCard>

  <ReleaseFeatureCard title="Threads your way">
    Room managers can [make threads required, encouraged, enabled, or disabled](/guides/operations/community-structure/#threading-mode)
    for each room. [My Threads](/getting-started/threads/) becomes an inbox that shows the latest reply of
    each conversation you follow.
  </ReleaseFeatureCard>

  <ReleaseFeatureCard title="Better rooms">
    Preview a room before you join it. Room names can now contain spaces,
    emoji, and any writing system. Room managers can turn on
    [slow mode](/guides/operations/community-structure/#slow-mode).
  </ReleaseFeatureCard>

  <ReleaseFeatureCard title="A new attachment viewer">
    [Zoom into images](/getting-started/message-formatting/#view-attachments), browse the images of a message as a gallery, and add
    descriptions that screen readers use. Uploads show their progress, and a
    failed upload stays in the composer so you can try again.
  </ReleaseFeatureCard>

  <ReleaseFeatureCard title="Clearer calls">
    [Voice boosting and an optional noise gate](/guides/infrastructure/voice-calls/#device-preferences-and-microphone-test) make voices easier to hear. Set
    the volume of each participant, and see a warning when a connection is
    poor. Chatto remembers your devices.
  </ReleaseFeatureCard>

  <ReleaseFeatureCard title="Profiles with a bio">
    Add a [Markdown bio](/getting-started/message-formatting/#profile-bios) to your profile and share your local time if you want.
    Your time zone stays private until you share it.
  </ReleaseFeatureCard>

  <ReleaseFeatureCard title="21 languages">
    Chatto is now available in 21 languages with 29 regional variants.
  </ReleaseFeatureCard>

  <ReleaseFeatureCard title="Make Chatto look your way">
    Choose an [accent color, a flat or 3D style](/getting-started/appearance/), and a contrast level from soft
    to pure black and white.
  </ReleaseFeatureCard>

  <ReleaseFeatureCard title="Pinned messages" size="small">
    Room managers can [pin important messages](/guides/operations/pinned-messages/). Pins appear in the room sidebar.
  </ReleaseFeatureCard>

  <ReleaseFeatureCard title="Bluesky and Mastodon previews" size="small">
    Social posts show as native cards with images, quoted posts, and hidden
    content warnings.
  </ReleaseFeatureCard>

  <ReleaseFeatureCard title="See who reacted" size="small">
    Open the reactions of a message to see who used each emoji.
  </ReleaseFeatureCard>

  <ReleaseFeatureCard title="Presence you control" size="small">
    Chatto no longer sets you to Away automatically. Your status applies to all
    your devices on a server.
  </ReleaseFeatureCard>
</ReleaseFeatureGrid>

### Other noteworthy changes

- Start a thread together with its first message with **Post as thread**.
- Show a thread beside the room, in a pane that you
  can resize.
- The message menu can copy the text, a link, an image,
  or a link to the message. Code blocks have a copy button.
- Edited messages show an **Edited** label. A thread
  reply that was also posted to the room links to that copy.
- [Put a link in angle brackets](/getting-started/message-formatting/#prevent-a-link-preview), such as
  `<https://example.com>`, to send it without a preview.
- HTML attachments open in a sandboxed preview
  only after you select **Show preview**. Download always gives you the
  original file.
- When the server processes videos, you can seek in new
  videos.
- The room timeline shows when a call starts and
  ends. The screen stays awake during a call.
- Send yourself a test push notification from
  notification settings.
- Unjoined rooms in a room group collapse into one row.
  Rooms, room groups, and servers have context menus.
- Bots have a **BOT** badge beside their name.
- The installed app shows your recent chats before it
  reconnects to the server.

### Fixes

- A new direct message stays hidden from the other person until you send the
  first message.
- Pasted Markdown links keep their label and destination when you edit the
  message.
- An edit that happens at the same time as a deletion cannot restore the
  deleted message.
- Audio, GIFs, and videos continue to play when reactions change.
- Images and videos fit inside narrow messages.
- The Files panel loads only when you open it.
- Members with `message.manage` can edit their own messages after the edit
  window.
- Each member can add up to 20 different reactions to one message.
- The installed app asks before it reloads for an update. It no longer reloads
  while you write.
- The chat stays visible while Chatto reconnects.
- Active members stay signed in. Chatto no longer signs them out at a fixed
  deadline.
- The app badge shows only important activity.
- Push notifications on a custom domain open Chatto on that domain.
- Email verification codes are valid for 30 minutes.

## Running Chatto

<ReleaseFeatureGrid>
  <ReleaseFeatureCard title="Privileged mode" size="large">
    Administrative and moderation permissions stay off during normal use. Enable
    [privileged mode](/guides/operations/permissions/#privileged-mode) for 15 minutes when you need them. The event log records
    each activation.
  </ReleaseFeatureCard>

  <ReleaseFeatureCard title="Set up a server in the browser" size="large">
    A new server opens a setup wizard for the server name and the owner
    account. You do not need a command line or email delivery for the first
    login.
  </ReleaseFeatureCard>

  <ReleaseFeatureCard title="Invite links">
    Create single-use or reusable [invite links](/guides/operations/identity-login/#invite-only-account-creation) with an expiry date. Set account
    creation to invite-only to admit new members only through these links.
  </ReleaseFeatureCard>

  <ReleaseFeatureCard title="Room management where the room is">
    Room settings open from the room itself. Give a member `room.manage` for one
    room or room group, without access to server administration.
  </ReleaseFeatureCard>

  <ReleaseFeatureCard title="More precise permissions">
    [New permissions](/guides/operations/permissions/) control reading messages, calls, and direct messages
    separately. Moderators can remove a member from a room, with an optional
    suspension.
  </ReleaseFeatureCard>

  <ReleaseFeatureCard title="More ways to sign in">
    Members can add several [verified email addresses](/guides/operations/identity-login/#verified-email-addresses).
    Operators can [turn off password login](/guides/operations/identity-login/#sso-only-login)
    for SSO-only servers, and [send email through JMAP](/guides/operations/identity-login/#transactional-email).
  </ReleaseFeatureCard>

  <ReleaseFeatureCard title="Connect from any Chatto client">
    [Clients on other origins](/guides/operations/cross-server-connections/) connect without allowlists. Members approve each
    client, and administrators can trust or block it.
  </ReleaseFeatureCard>

  <ReleaseFeatureCard title="Neighbors">
    [Recommend other Chatto servers](/guides/operations/neighbors/) in a public directory. Members find them in
    the Server Directory. This feature is experimental.
  </ReleaseFeatureCard>

  <ReleaseFeatureCard title="Operator CLI for rooms and messages">
    Create and list rooms, add members, upload attachments, and import
    historical messages with the [operator CLI](/guides/operations/operator-cli/).
  </ReleaseFeatureCard>

  <ReleaseFeatureCard title="Faster restarts, less memory">
    Servers with a long history replay faster and use less memory. Optional
    encrypted snapshots shorten restarts further.
  </ReleaseFeatureCard>

  <ReleaseFeatureCard title="Delete member accounts" size="small">
    Administrators can delete another member's account from member
    administration.
  </ReleaseFeatureCard>

  <ReleaseFeatureCard title="Community badges" size="small">
    Show online and registered member counts on your website with
    [Shields.io badges](/guides/integrations/community-shields/).
  </ReleaseFeatureCard>
</ReleaseFeatureGrid>

### Other noteworthy changes

- Server diagnostics show the health of background workers
  and asset cleanup.
- Back up and restore a Docker Compose installation
  with `docker compose run`. See
  [Backup and restore](/guides/operations/backup-restore/).
- The operator CLI can look up users by login or email address and clear a
  username cooldown.
- [Password managers](/guides/operations/identity-login/#password-managers) find the password change page
  through `/.well-known/change-password`. Make sure that your reverse proxy
  forwards this path.
- Set `nats.embedded.sync_interval` to control how often
  embedded NATS writes to disk.
- The Chatto binary is smaller.

### Fixes

- A server process recovers by itself after a short NATS outage.
- Chatto sends Web Push requests only to public HTTPS addresses.
- The event log no longer contains password data.
- Administrators can rename their own account and reset their own username
  cooldown.
- Permission changes show a pending state.
- The server description limit applies before you save.
- The Docker Compose setup restarts services after a failure and uses real
  health checks.

  <ReleaseFeatureCard title="Webhooks in and out" size="large">

    including [Grafana alerts](/guides/integrations/grafana/) without a custom
    template. [Outbound webhooks](/guides/integrations/bot-accounts/#outbound-webhooks) send signed requests when someone
    mentions a bot or sends it a direct message.
  </ReleaseFeatureCard>

  <ReleaseFeatureCard title="Realtime protocol 4">
    The [realtime connection](/guides/integrations/realtime-protocol/) starts from an exact snapshot, sends semantic
    events, and resumes after a short disconnection without a full reload.
  </ReleaseFeatureCard>

  <ReleaseFeatureCard title="Model Context Protocol">
    Connect AI assistants to Chatto through [MCP](/guides/integrations/mcp/). They read and post messages
    with the permissions of the member or bot that authorized them. This feature
    is experimental.
  </ReleaseFeatureCard>

### Other noteworthy changes

- Transfer a bot to a new owner. Its permissions
  and API keys stay.
- Chatto keeps outbound webhook delivery logs for 7
  days.
- Native apps and command-line tools can receive
  OAuth callbacks on a loopback address.
- Server discovery reports the server version.
- Large lists, such as the room directory and role
  members, now return pages.
- Find archived rooms through the room directory
  API.

## Upgrade Notes

### Review your permissions before you upgrade

**Chatto does not change the permissions of an existing server.** Version 0.5
adds new permissions. A new server gets default grants for them, but an
upgraded server does not. If you do not add these grants, members cannot read
messages after the upgrade.

Do these steps on every upgraded server:

- **Grant `message.read`.** Without it, members see a permission error instead
  of messages in channels and direct messages. Only the owner can still read.
  To keep the 0.4 behavior, allow `message.read` for `everyone` at server scope.
- **Grant `room.remove-member`** to the moderator and admin roles.
  `room.ban-member` has no effect in 0.5. Active bans continue as suspensions.
- **Grant `user.invite` and `bot.manage`** to the admin role. Grant
  `bot.create` to `everyone` if members can create bots.
- **Grant `room.manage`** to delegated room managers. Room group management
  used `role.manage` in 0.4.
- **Check thread posting.** `message.post` now also allows thread replies. A
  0.4 setup that allowed `message.post` and denied `message.post-in-thread` now
  allows replies.
- **Check `everyone` denies.** An allow for a named role or a user now
  overrides an `everyone` deny at the same or a narrower scope.

Call permissions are new too. Chatto grants them to `everyone` on upgrade, so
existing call access does not change.

Administrators, moderators, and the owner must now enable privileged mode before
they use their administrative permissions. This also applies to custom
`room.create` grants. Owners also need privileged mode to see, join, or read
rooms that deny these actions to `everyone`, and to post in the announcements
room. Give an owner the `admin` role or a room-level allow if they need this
access during normal use.

See [Permissions](/guides/operations/permissions/) for the complete list.

### Upgrade procedure

- Make a backup before you upgrade. Back up S3 assets and encryption keys
  separately.
- Stop every 0.4 server process and worker before you start 0.5. Do not use a
  rolling update. Upgrade the bundled client at the same time.
- You cannot go back to 0.4 after a 0.5 server accepts traffic. To roll back,
  restore the backup. Writes after the backup are lost.

### Configuration

- **Video processing moved.** Rename `video.ffmpeg_path`,
  `video.ffprobe_path`, `video.max_concurrent`, and `video.temp_dir` to
  `asset_processing.ffmpeg_path`, `asset_processing.ffprobe_path`,
  `asset_processing.max_concurrent_jobs`, and `asset_processing.temp_dir`. Set
  `asset_processing.enabled = true`, or new videos stay in processing. Chatto
  ignores the old keys without an error. New videos use HLS; existing MP4 videos
  continue to play. See [Video processing](/guides/infrastructure/video-processing/).
- Remove `webserver.oauth_redirect_origins`. Clients on other origins no longer
  need configuration. Use `webserver.allowed_origins` only for additional
  origins of the bundled client behind your reverse proxy. Chatto does not
  start if an origin has a path, or if one host has both an HTTP and an HTTPS
  origin.
- The Content Security Policy is now enforced. The browser blocks scripts that a
  reverse proxy adds to the page, and other sites cannot show Chatto in an
  iframe.
- Search is off by default. To use it, enable `[search]` and
  `[search_provider]`. See [Search](/guides/operations/search/).
- The CLI no longer accepts `--passphrase`. Use `--passphrase-file` or
  `--passphrase-stdin` in scripts.
- The `chatto_service_info` metric is removed. Use `chatto_model_info`.

### What members notice

- The notification list starts empty. Notification settings start with the new
  defaults.
- Members stay signed in to the bundled client. Members of other servers in the
  multi-server client, and OAuth clients, sign in again once.
- The 0.5 client does not connect to 0.4 servers.

### Custom clients and bots

Regenerate every custom client from the 0.5 protobufs. The public API and the
realtime protocol have breaking changes, and 0.5 servers accept only realtime
protocol 4. See [API compatibility](/guides/integrations/api-compatibility/).
