机器人让外部工具能够在 Chatto 中发布消息和回复对话。创建机器人帐户，授予它访问所需房间的权限，然后通过 API 密钥或 webhook 连接你的工具。机器人软件需要单独运行。

以下步骤将配置一个发布部署更新的机器人。你需要创建机器人的权限，并能访问目标房间。

## 选择工具的连接方式

有三种连接方式。一个机器人可以同时使用多种方式。

- **传入 webhook：你的工具 → Chatto。**为告警服务或自动化工具提供一个用于发布消息的 URL。
- **API 密钥：你的程序 → Chatto。**给自己的机器人程序一个密钥，让它读取消息、发送回复或执行你允许的其他 API 操作。
- **传出 webhook：Chatto → 你的工具。**向 Chatto 提供一个端点，以便在有人提及机器人或向它发送私信时通知该端点。你的工具处理事件，需要回复时使用 API 密钥。

发布部署更新时，使用传入 webhook。要让机器人回复提及或私信，使用传出 webhook 接收消息，使用 API 密钥发送回复。

## 1. 创建机器人帐户

1. 在机器人将运行的服务器上打开**服务器管理 → 机器人**。
2. 选择**创建机器人**。本例使用 `release-bot` 作为用户名，**发布更新**作为显示名称。用户名标识帐户；显示名称是成员在消息旁看到的名称。
3. 创建机器人。Chatto 只显示一次 API 密钥。如果要使用 API，请将密钥保存到集成的机密存储中。关闭对话框后无法再次查看该密钥。
4. 打开机器人的详情页。在资料中填写简短说明，例如“发布来自发布流水线的部署结果”。

如果无法使用**创建机器人**，请向管理员申请 `bot.create` 权限。拥有机器人意味着可以管理该机器人；管理所有机器人的权限需要单独授予。

如果工具仅使用传入 webhook，就不需要 API 密钥。请在**集成 → API 密钥**中撤销未使用的初始密钥。

## 2. 授予一个房间的访问权限

新机器人没有任何权限。它不会继承所有者的角色，也不会继承 `everyone` 角色的权限。加入房间和有权在该房间发布消息是两个独立要求。

1. 打开机器人的**权限**标签页。
2. 找到部署更新房间对应的列。
3. 在矩阵顶部的**已加入**行中选择该房间，并确认成员资格变更。
4. 为该房间允许 `message.post`。不相关的权限保持未设置。

部署机器人不需要读取权限。在房间列中授予 `message.post`，可将发帖范围限制在该房间。服务器级别的授权会跨房间生效。

你还需要有权将机器人添加到房间。已归档房间和房间停权可能阻止加入。机器人自己的 `room.join` 权限用于通过 API 加入房间，不能替代**已加入**行。

### 机器人的权限不能超出所有者的权限

每项机器人授权都受人类所有者在相同范围内的当前权限限制。已保存的授权可能未生效：矩阵中的锁表示所有者的权限阻止了该授权。如果所有者失去访问权限，机器人也会失去相同权限。退出登录不会停止机器人。

某些授权需要特权模式。如果 Chatto 要求启用该模式，请先启用，再添加授权。

## 3. 连接传入 webhook

1. 在机器人的详情页打开**集成**。
2. 在**传入 Webhook**下选择**创建 Webhook**。
3. 以调用方命名，例如**发布流水线**。
4. 将部署更新房间选为**目标房间**。
5. 创建 webhook，将完整 URL 复制到工具的 webhook 配置中。保留 URL 中的 `?room_id=…` 部分。

配置工具发送 HTTP **POST**，使用 `Content-Type: application/json` 和以下请求体：

```json
{
  "text": "部署完成：版本 **0.5** 已可测试。"
}
```

选定的房间已包含在 URL 中，因此此请求不需要 `channel` 字段。如果改选**在每个请求中选择**，请在 JSON 中包含 `"channel": "YOUR_ROOM_ID"`。使用房间 ID，而不是名称。

选择目标只是在 URL 中添加房间 ID。调用方可以修改该 ID，向机器人有权发帖的任何房间发布消息。要将 webhook 限制到一个房间，请只授予机器人在该房间发帖的权限。

## 4. 发送测试并检查结果

使用外部工具的测试功能。成功的传入请求会返回 HTTP `200` 和文本 `ok`。在 Chatto 中，消息应出现在选定的房间里，发送者为**发布更新**，带有 **BOT** 标签，且“0.5”为粗体。

如果请求失败，请检查响应：

- **`401 invalid_token`：**URL 不完整、无效或已撤销。如果不再持有完整 URL，请创建新的传入 webhook。
- **`404 channel_not_found`：**检查房间 ID、机器人的成员资格、其 `message.post` 授权，以及所有者在该房间的发帖权限。
- **`400 invalid_payload`：**发送有效 JSON，包含非空消息文本和房间 ID。如果 URL 和请求体中都有房间 ID，两者必须一致。房间策略和消息大小限制仍然适用。
- **消息出现两次：**重试可能创建另一条消息。传入 webhook 不提供用于消除重复的幂等键。

测试成功后，配置工具在部署完成时调用 webhook。

## 创建会回复人的机器人

为机器人程序配置它的 Chatto API 密钥。将密钥保存在程序的机密配置中。API 请求通过 `Authorization: Bearer YOUR_API_KEY` 请求头进行身份验证。

选择机器人所需的权限：

- **仅在被点名时回复：**授予 `message.read-interactions` 和 `message.post-in-interactions`。机器人可以读取它发起的完整讨论串、有人直接提及它的讨论串，以及它的私信。因此，提及机器人也可能使它获得该讨论串中更早消息的访问权限。
- **读取房间，但仅在被点名时回复：**授予 `message.read` 和 `message.post-in-interactions`。
- **读取全部消息并发起对话：**授予 `message.read` 和 `message.post`。

将授权应用于目标房间。私信使用矩阵中的**私信**范围。所有者的权限仍然限制这些授权。

### 告诉程序何时应当回复

如果你的程序接收 Chatto webhook 事件：

1. 打开**集成 → 出站 Webhook → 创建 Webhook**。
2. 输入名称和程序的公共 HTTPS 端点。
3. 如果接收方要求 **Authorization 请求头**，请输入它期望的完整值，包括 `Bearer` 之类的前缀。
4. 如果接收方验证 Chatto webhook 签名，请将签名密钥复制到其配置中。该密钥只显示一次。
5. 在机器人可读取的房间中提及它，或向它发送私信。检查接收方日志及机器人在 Chatto 中的回复。

端点会接收直接提及机器人或属于其私信的新消息。普通房间消息、编辑、回应及机器人自己发送的消息不会触发这些 webhook。房间讨论串中后续的普通回复也不会触发，除非再次提及机器人。

接收方应以 HTTP 2xx 响应接受事件，再通过 API 发送聊天回复。Chatto 会忽略 HTTP 响应体。投递可能重复，因此接收方必须使用投递 ID，避免重复处理。如果程序需要所有可读取的活动，请使用 Chatto 实时 API，而不是仅处理提及和私信的 webhook。

事件载荷、签名验证和 API 操作请参阅[机器人 webhook 参考](https://docs.chatto.run/reference/bot-webhooks/)及 [API 参考](https://docs.chatto.run/reference/connectrpc-api/)。

传出 webhook 会将消息文本以及消息、作者、房间和机器人的标识符发送到配置的端点。接收方还能看到 Chatto 服务器的出口 IP 地址。如果机器人会将消息转发给 AI 提供商或其他服务，请在将它用于成员对话之前向成员说明。

### 如果机器人没有回复

检查程序是否收到事件。在传出 webhook 下打开**最近的失败**，查看记录的投递错误。检查端点是否启用、可访问、接受已配置的身份验证，并返回不带重定向的 2xx 响应。失败列表为空并不能证明投递成功。

如果事件已到达但没有回复，请检查程序的 API 密钥、回复操作，以及机器人的有效读取和发帖权限。

## 维护集成

- **更换凭据：**创建新的具名密钥或 webhook，更新调用方，测试后撤销旧凭据。API 密钥不会自动过期。切勿将真实密钥或带凭据的 URL 粘贴到聊天或源代码管理中。
- **暂时停止传出投递：**在端点上选择**暂停**。**恢复**允许接收新事件，但不会重放暂停期间的事件。
- **将机器人交给另一位所有者：**具有 `bot.manage` 权限的帐户可以使用**重新分配所有者**。机器人的有效权限会立即跟随新所有者。现有密钥仍有效；如果旧操作者必须失去访问权限，请更换凭据。
- **删除所有者帐户：**先重新分配需要长期运行的机器人。删除人类所有者也会删除其拥有的机器人。
- **向成员展示机器人的能力：**打开机器人资料，查看**所有者**及**它能做什么**。更改房间或所有权后，请重新检查权限。
