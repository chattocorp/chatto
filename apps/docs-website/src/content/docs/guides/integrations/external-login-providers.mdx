Add a login provider as a `[[auth.providers]]` entry in `chatto.toml`. The
login page shows one button for each provider. Sign-in and account linking open
in a popup, so users must allow popups for Chatto.

## Supported providers

| Type | Use for |
| ---- | ------- |
| `oidc` | Any standard OIDC provider, for example [Pocket ID](#example-pocket-id) |
| `github` | GitHub OAuth apps |
| `gitlab` | GitLab OAuth applications |
| `google` | Google OAuth clients |
| `discord` | Discord OAuth2 applications |

Self-hosted OIDC providers include [Pocket ID](https://pocket-id.org/),
[Kanidm](https://kanidm.com/), [VoidAuth](https://github.com/voidauth/voidauth),
[Portier](https://portier.github.io/), [Authelia](https://www.authelia.com/),
[Dex](https://dexidp.io/), [Authentik](https://goauthentik.io/), and
[Keycloak](https://www.keycloak.org/). Make sure that your provider supports
standard OIDC discovery.

## Provider IDs

Each provider needs a stable `id`, for example `github-main` or
`staff-google`. The ID is part of the callback URL, and Chatto stores it in
each account link.

- Use short, URL-safe IDs. Do not use spaces, `/`, `?`, or `#`.
- Do not change an ID after users link accounts. A change disconnects those
  links.

## Callback URLs

Register this callback URL with each provider:

```txt
https://chat.example.com/auth/providers/{providerID}/callback
```

Chatto makes the URL from `webserver.url`. Set `webserver.url` to the public
HTTPS address of your server.

Older OIDC registrations can also use `/auth/oidc/callback`. Use the
provider-specific URL for new registrations.

## Configuration

<Tabs>
<TabItem label="OIDC">

```toml
[webserver]
url = "https://chat.example.com"

[[auth.providers]]
id = "company-sso"
type = "oidc"
label = "Company SSO"
issuer_url = "https://idp.example.com"
client_id = "..."
client_secret = "<generate-me>"
auto_provision = false
# Optional: override the method from OIDC discovery.
# token_endpoint_auth_method = "client_secret_basic"
```

`issuer_url` is an absolute `http` or `https` URL. Chatto uses OIDC discovery
from this issuer and verifies the ID token.

</TabItem>
<TabItem label="GitHub, GitLab, Google, Discord">

```toml
[webserver]
url = "https://chat.example.com"

[[auth.providers]]
id = "github-main"
type = "github"   # or "gitlab", "google", "discord"
label = "GitHub"
client_id = "..."
client_secret = "<generate-me>"
auto_provision = false
```

</TabItem>
<TabItem label="Environment">

```bash
CHATTO_AUTH_PROVIDERS_0_ID=company-sso
CHATTO_AUTH_PROVIDERS_0_TYPE=oidc
CHATTO_AUTH_PROVIDERS_0_LABEL="Company SSO"
CHATTO_AUTH_PROVIDERS_0_ISSUER_URL=https://idp.example.com
CHATTO_AUTH_PROVIDERS_0_CLIENT_ID=...
CHATTO_AUTH_PROVIDERS_0_CLIENT_SECRET=<generate-me>
CHATTO_AUTH_PROVIDERS_0_AUTO_PROVISION=false

CHATTO_AUTH_PROVIDERS_1_ID=github-main
CHATTO_AUTH_PROVIDERS_1_TYPE=github
CHATTO_AUTH_PROVIDERS_1_LABEL=GitHub
CHATTO_AUTH_PROVIDERS_1_CLIENT_ID=...
CHATTO_AUTH_PROVIDERS_1_CLIENT_SECRET=<generate-me>
```

Indexes start at `0` and must not have gaps. Fields are `ID`, `TYPE`, `LABEL`,
`CLIENT_ID`, `CLIENT_SECRET`, `TOKEN_ENDPOINT_AUTH_METHOD`, `ISSUER_URL`,
`SCOPES` (comma-separated), `REQUEST_EMAIL`, `AUTO_PROVISION`, and
`PROVIDER_OPTIONS_<KEY>`.

If you set any `CHATTO_AUTH_PROVIDERS_<index>_*` variable, Chatto ignores the
providers in `chatto.toml`. Chatto also accepts the older
`CHATTO_AUTH_OIDC_ENABLED`, `_ISSUER_URL`, `_CLIENT_ID`, `_CLIENT_SECRET`, and
`_LABEL` variables. They create one `oidc` provider with `id = "oidc"`. Do not
use them together with counted variables.

</TabItem>
</Tabs>

### Token endpoint authentication

For `oidc` providers only, `token_endpoint_auth_method` can be
`client_secret_basic`, `client_secret_post`, or `none`. Basic and POST need a
`client_secret`. `none` needs no secret.

When you do not set it, public clients use `none`. Other clients use Basic if
discovery lists it, and POST if not. If discovery does not list methods, Chatto
uses Basic. Chatto does not try a second method after a failed exchange.

## CIMD public clients

If your OIDC provider supports
[Client ID Metadata Documents (CIMD)](https://client.dev/), you do not need to
register a client ID and secret:

```toml
[[auth.providers]]
id = "company-sso"
type = "oidc"
label = "Company SSO"
issuer_url = "https://idp.example.com"
client_id = "https://chat.example.com/oauth/client-metadata.json"
auto_provision = true
```

Set `client_id` to exactly `{webserver.url}/oauth/client-metadata.json` and do
not set `client_secret`. Chatto publishes its callback URL and client metadata
at that URL.

## Scopes

Chatto requests only the scopes that identify the account. It requests email
scopes only when `request_email = true`. The default is `false`.

| Type | Default scopes | With `request_email = true` |
| ---- | -------------- | --------------------------- |
| `oidc` | `openid`, `profile` | `openid`, `profile`, `email` |
| `github` | none | `read:user`, `user:email` |
| `gitlab` | none | `read_user` |
| `google` | `openid`, `profile` | `openid`, `profile`, `email` |
| `discord` | `identify` | `identify`, `email` |

To set different scopes:

```toml
[[auth.providers]]
# ...
scopes = ["openid", "profile", "groups"]
```

Chatto always adds `openid` for OIDC providers.

## Auto-provisioning

`auto_provision` controls whether a new provider identity can create an
account.

- `false` (default): Chatto returns the user to the login page with an
  explanation. Existing users can link the provider from account settings.
- `true`: the user confirms a username, and then Chatto creates the account.

With [invite-only account creation](/guides/operations/identity-login/#invite-only-account-creation),
new accounts also need an invite link.

## Account matching

Chatto matches a login by provider identity, never by email address:

- OIDC: the verified issuer and the subject.
- OAuth providers: the provider `id` and the provider user ID.

To link a provider, a user signs in, opens account settings, and confirms their
password or signs in again. An identity that is linked to a different account
cannot be linked. Removing a provider needs confirmation and keeps existing
sessions.

An account without an email address has no password until the user sets one.
Email password reset needs a verified email address. On SSO servers without
email, make sure that each user keeps at least one working provider link.

## Verified email and verified factors

A linked identity is enough to sign in and counts toward `limits.max_users`,
even without an email address. Chatto stores a provider email as a verified
email only when the provider confirms it:

| Provider | Chatto stores a verified email when |
| -------- | ----------------------------------- |
| `oidc` | `email` is present and `email_verified = true` |
| `github` | GitHub returns a verified primary email |
| `google` | The profile marks the email as verified |
| `discord` | The profile has `verified = true` |
| `gitlab` | Never |

Password reset and `owners.emails` need a verified email. A linked identity
alone does not make a user an owner.

## Discovery fields

Clients find the configured providers through
`chatto.discovery.v1.ServerDiscoveryService.GetServer`. The `login.providers`
field lists each provider ID, type, label, and login URL:

```sh
curl -X POST https://chat.example.com/api/connect/chatto.discovery.v1.ServerDiscoveryService/GetServer \
  -H 'Content-Type: application/json' \
  -H 'Connect-Protocol-Version: 1' \
  --data '{}'
```

## Example: Pocket ID

[Pocket ID](https://pocket-id.org/) lets people sign in with passkeys. This
example uses `https://chat.example.com` for Chatto and `https://id.example.com`
for Pocket ID. Both must use HTTPS and must reach each other at these URLs.

<Steps>

1. **Create the client.** In Pocket ID, open **OIDC Clients** and select
   **Add OIDC Client**:

   | Field | Value |
   | --- | --- |
   | Name | `Chatto` |
   | Callback URL | `https://chat.example.com/auth/providers/pocket-id/callback` |
   | Client Launch URL | `https://chat.example.com` (optional) |

   Save the client. Copy the **Client ID** and **Client Secret**.

2. **Give users access.** In **Allowed User Groups**, select the groups that
   can use Chatto, or select **Unrestrict** for all users. Until you do this,
   Pocket ID denies access to everyone. Pocket ID groups do not give Chatto
   roles or permissions.

3. **Configure Chatto.** Set `issuer_url` to the Pocket ID base URL, without
   `/.well-known/openid-configuration`:

   <Tabs>
   <TabItem label="TOML">

   ```toml
   [webserver]
   url = "https://chat.example.com"

   [[auth.providers]]
   id = "pocket-id"
   type = "oidc"
   label = "Pocket ID"
   issuer_url = "https://id.example.com"
   client_id = "<pocket-id-client-id>"
   client_secret = "<generate-me>"
   auto_provision = false
   ```

   </TabItem>
   <TabItem label="Environment">

   ```bash
   CHATTO_WEBSERVER_URL=https://chat.example.com
   CHATTO_AUTH_PROVIDERS_0_ID=pocket-id
   CHATTO_AUTH_PROVIDERS_0_TYPE=oidc
   CHATTO_AUTH_PROVIDERS_0_LABEL="Pocket ID"
   CHATTO_AUTH_PROVIDERS_0_ISSUER_URL=https://id.example.com
   CHATTO_AUTH_PROVIDERS_0_CLIENT_ID=<pocket-id-client-id>
   CHATTO_AUTH_PROVIDERS_0_CLIENT_SECRET=<generate-me>
   CHATTO_AUTH_PROVIDERS_0_AUTO_PROVISION=false
   ```

   </TabItem>
   </Tabs>

   Replace `<generate-me>` with the Pocket ID client secret.

4. **Choose how accounts are created.** Keep `auto_provision = false` on an
   existing or invite-only server. Users then link Pocket ID from account
   settings. Set it to `true` to let all allowed Pocket ID users create
   accounts.

5. **Restart and test.** Restart Chatto, open the login page, and select
   **Pocket ID**. With `auto_provision = false`, first sign in to an existing
   account, link Pocket ID, sign out, and then sign in with Pocket ID.

</Steps>

To get a verified email from Pocket ID, add `request_email = true`. Chatto
stores the address only when Pocket ID also returns `email_verified = true`.

## Troubleshooting

| Symptom | Solution |
| ------- | -------- |
| The provider rejects the callback | Make the registered callback URL match `https://chat.example.com/auth/providers/{providerID}/callback` exactly, including `https`. Set `webserver.url` to the public HTTPS URL. |
| Chatto cannot discover the provider | Set `issuer_url` to the public base URL of the provider, without a discovery path. For Pocket ID, `APP_URL` must also be that URL. |
| Pocket ID says that the user is not allowed | Select **Allowed User Groups**, or select **Unrestrict**. |
| Chatto does not create an account | Set `auto_provision = true`, or sign in to an existing account and link the provider first. |
| Links stopped working after a change | Restore the original provider `id` and its callback URL. |
