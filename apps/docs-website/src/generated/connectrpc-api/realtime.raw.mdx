### RealtimeCaughtUp

Confirms that recovery is complete and live delivery has begun.

<a id="chatto-realtime-v1-RealtimeClientFrame"></a>

### RealtimeClientFrame

Client-to-server frame for Chatto's protobuf WebSocket realtime protocol.

Clients send binary protobuf frames to `/api/realtime`. The first frame must
be `hello`. After the server replies with `hello`, clients send
`subscribe_events` to start one authorized public event stream.

| Field | Type | Description |
| --- | --- | --- |
| `frame.hello` | [`RealtimeClientHello`](#chatto-realtime-v1-RealtimeClientHello) | Opens the protocol session and optionally carries a bearer token. |
| `frame.subscribe_events` | [`RealtimeSubscribeEvents`](#chatto-realtime-v1-RealtimeSubscribeEvents) | Starts the caller's authorized public event stream. |
| `frame.ping` | [`RealtimePing`](#chatto-realtime-v1-RealtimePing) | Application-level ping. The server replies with `pong`. |

<a id="chatto-realtime-v1-RealtimeSnapshot"></a>

### RealtimeSnapshot

One resource family from an authorized snapshot of `ServerContentView`.

The server sends all snapshot frames between `subscribed(SNAPSHOT)` and
`caught_up`. The client must discard an incomplete snapshot if the socket
closes before `caught_up`. List values replace the complete local family.
Large and paginated resources, such as message history, are not part of the
snapshot and remain available through ConnectRPC.

| Field | Type | Description |
| --- | --- | --- |
| `resource.server` | `chatto.api.v1.ServerPublicProfile` | Current public server profile. |
| `resource.rooms` | `chatto.api.v1.ListRoomsResponse` | Complete visible room directory. |
| `resource.room_groups` | `chatto.api.v1.ListRoomGroupsResponse` | Complete visible room-group layout. |
| `resource.users` | `chatto.api.v1.BatchGetUsersResponse` | Users referenced by this snapshot. This is not the server directory. |
| `resource.active_calls` | `chatto.api.v1.ListActiveCallsResponse` | Complete visible active-call state. |

<a id="chatto-core-event-v1-EventFieldSurface"></a>

### EventFieldSurface

EventFieldSurface controls whether an Event payload field can exist in
stored EVT bytes, an authorized public event, or both.

| Name | Number | Description |
| --- | --- | --- |
| `EVENT_FIELD_SURFACE_UNSPECIFIED` | `0` | The field has no explicit public surface. EVT can store it. Public projection omits it at a payload root; nested fields can inherit a classified parent message's surface. This default-deny value is intentional: a new persisted field must not become public by accident. |
| `EVENT_FIELD_SURFACE_SHARED` | `1` | The field can exist in EVT and in an authorized public event. |
| `EVENT_FIELD_SURFACE_STORAGE_ONLY` | `2` | The field can exist only in EVT. Public projection removes it. |
| `EVENT_FIELD_SURFACE_CLIENT_ONLY` | `3` | The field can exist only in an authorized public event. EVT rejects it. |


<a id="chatto-realtime-v1-RealtimeInitialState"></a>

### RealtimeInitialState

Startup behavior when a subscription cannot resume from its cursor.

| Name | Number | Description |
| --- | --- | --- |
| `REALTIME_INITIAL_STATE_UNSPECIFIED` | `0` | Invalid value. The server rejects subscriptions that use it. |
| `REALTIME_INITIAL_STATE_LIVE_ONLY` | `1` | Start at the current event boundary without sending current resources. |
| `REALTIME_INITIAL_STATE_SNAPSHOT` | `2` | Send an exact authorized snapshot before later public events. |


<a id="chatto-realtime-v1-RealtimeRecoveryMode"></a>

### RealtimeRecoveryMode

Recovery path selected for one subscription.

| Name | Number | Description |
| --- | --- | --- |
| `REALTIME_RECOVERY_MODE_UNSPECIFIED` | `0` | Invalid value. |
| `REALTIME_RECOVERY_MODE_LIVE_ONLY` | `1` | Delivery starts at the current boundary without current resources or history. |
| `REALTIME_RECOVERY_MODE_SNAPSHOT` | `2` | The server sends an exact authorized snapshot before later events. |
| `REALTIME_RECOVERY_MODE_RESUME` | `3` | Durable events resume after the supplied cursor. |
