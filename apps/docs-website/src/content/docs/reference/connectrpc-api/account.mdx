## MyAccountService

Self-service account, profile, display preference, presence,
custom-status, external identity, and account lifecycle commands for the
authenticated user.

<a id="chatto-api-v1-MyAccountService-UpdateProfile"></a>

### UpdateProfile

Updates the authenticated user's login, display name, and/or bio.

```http
POST /api/connect/chatto.api.v1.MyAccountService/UpdateProfile
```

<a id="chatto-api-v1-UpdateProfileRequest"></a>

#### Input: UpdateProfileRequest

Request to update the authenticated user's profile. Human and bot accounts
use this same self-service operation. update_mask selects fields to apply
or reset. Fields outside the mask stay unchanged.

| Field | Type | Description |
| --- | --- | --- |
| `display_name` | `optional string` | New non-empty display name. The server also rejects control and confusing invisible characters. |
| `login` | `optional string` | New login identifier, when changing it. The server accepts ASCII letters, digits, period, underscore, and hyphen, starting with a letter or digit. |
| `bio` | `optional string` | New Markdown biography, when changing it. Empty clears the bio. |
| `update_mask` | `google.protobuf.FieldMask` | Editable fields to apply or reset: display_name, login, bio. Omit to infer populated fields; * selects all editable fields. An explicit empty mask is invalid. Unselected values are ignored. Selected absent values reset the field to its default, subject to field validation. |

#### Result: UpdateProfileResponse

Result of a profile update.

| Field | Type | Description |
| --- | --- | --- |
| `user` | [`User`](/reference/connectrpc-api/types/#chatto-api-v1-User) | Updated user profile. |

<a id="chatto-api-v1-MyAccountService-RequestEmailVerification"></a>

### RequestEmailVerification

Sends a six-digit code to an email address that the authenticated user
wants to add. The code expires after the server-configured email OTP
lifetime. The client can request a new code after expiry. The server must
have transactional email enabled. Returns ALREADY_EXISTS when the address
is already verified for the user, RESOURCE_EXHAUSTED after too many code
requests or attempts, and UNAVAILABLE when email delivery is disabled or
fails. Returns FAILED_PRECONDITION when the authenticated account does not
match expected_user_id.

```http
POST /api/connect/chatto.api.v1.MyAccountService/RequestEmailVerification
```

<a id="chatto-api-v1-RequestEmailVerificationRequest"></a>

#### Input: RequestEmailVerificationRequest

Request a short-lived verification code for an email address.

| Field | Type | Description |
| --- | --- | --- |
| `email` | `string` | New address to verify and add to the authenticated user's account. |
| `expected_user_id` | `string` | User ID that the client expects to be authenticated. |


<a id="chatto-api-v1-RequestEmailVerificationResponse"></a>

#### Result: RequestEmailVerificationResponse

Result of requesting an email verification code.


<a id="chatto-api-v1-MyAccountService-ConfirmEmailVerification"></a>

### ConfirmEmailVerification

Confirms a verification code and adds the address to the account. Returns
INVALID_ARGUMENT when the code is invalid or expired, and ALREADY_EXISTS
when another user already controls the address. Returns FAILED_PRECONDITION
when the authenticated account does not match expected_user_id.

```http
POST /api/connect/chatto.api.v1.MyAccountService/ConfirmEmailVerification
```

### SetPresence

Legacy live presence report, expiring after 60 seconds without refresh.
A saved private choice overrides this report, including user_selected.
New clients use SetPresencePreference for choices and RefreshPresence
every 30 seconds for liveness.

```http
POST /api/connect/chatto.api.v1.MyAccountService/SetPresence
```

<a id="chatto-api-v1-SetPresenceRequest"></a>

#### Input: SetPresenceRequest
