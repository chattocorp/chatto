---
title: Advertise Neighbor Servers
description: Maintain the public directory of friendly Chatto servers.
---

Use **Neighbors** to advertise friendly Chatto servers to your users. A
Neighbor is a recommendation. It is not a trust or reciprocal relationship.

## Add a Neighbor

1. Open **Server Configuration → Neighbors**.
2. Enter a hostname or URL, such as `chat.example.com` or a link to a room on
   that server.
3. Select **Add Neighbor**.

You need `server.manage-neighbors`. The broader `server.manage` permission also
includes this authority.

The administration page extracts the HTTP or HTTPS origin from the value. It
removes paths, queries, and fragments before storage. A server can advertise
at most 100 Neighbors. Chatto rejects its own `webserver.url` origin and each
exact
`webserver.allowed_origins` alias.

## Edit or delete a Neighbor

Use **Edit** to change one advertised origin. Use **Delete** to remove the
Neighbor. Chatto rejects a stale edit when another administrator changed the
same Neighbor first. Reload the list, review the current value, and try again.

The Neighbors panel loads each server's public profile, logo, and banner. Use
this information to review the advertised server before you keep or remove it.

The directory has no ordering contract. Clients must not use its response order
as a rank or preference.

## Understand Neighborhood discovery

Your Chatto server discovers its **Neighborhood** in the background. The
Neighborhood contains each Neighbor whose public profile loads. When a Neighbor
also advertises your server, the Neighborhood can also contain the servers
that this Neighbor recommends. Chatto adds such a server only when that server
advertises the recommending Neighbor back. It follows at most two of these
mutual hops.

Chatto refreshes the Neighborhood each hour. If a server did not respond,
Chatto tries again after ten minutes. After you add, edit, or delete a
Neighbor, the change appears in about two minutes. One refresh sends at most
150 directory requests and 120 profile requests. Chatto uses at most six
active requests, and each request has a ten-second timeout.

These requests go from your Chatto server to the other servers. Make sure that
your server can make outbound HTTPS requests to its Neighbors. If outbound
traffic is blocked, the Neighborhood is empty or incomplete. Chatto does not
contact servers on loopback, private, or link-local network addresses, and it
does not follow redirects.

Chatto keeps a copy of each server's logo and banner. It accepts an image only
from that server's origin, only with a GIF, JPEG, PNG, or WebP media type, and
only up to 5 MiB. Your server serves these copies, so a client can show the
Neighborhood without contacting the other servers. Backups do not include the
Neighborhood or its image copies. Chatto discovers them again after a restore.

## Use the Server Directory

Select **Add Server** in the Server Gutter to open the Server Directory. The
client asks each server that is registered on the device for its
[Neighborhood](#understand-neighborhood-discovery) and shows the combined
results. The client contacts only these registered servers. They already know
your IP address, so opening the Server Directory does not reveal it to other
servers. The client does not ask for consent.

The client removes duplicate origins, but it does not sort or rank the results.
Each result shows the servers whose recommendations are displayed. A direct
Neighbor of a registered server names that registered server. When more than
two servers recommend the same result, the card shows two server names and the
number of other recommendations. Server profile cards use a tapestry layout.

A result can show the server name, description, logo, and banner. The client
loads a logo or banner only from the registered server that supplied the
result. It loads the image without credentials or referrer data, does not
follow image redirects, and accepts only responses that declare a supported
raster image media type and contain at most 5 MiB.

The client sends one request to each registered server, with at most six
active requests and a ten-second timeout for each request. If a registered
server does not respond, the Server Directory shows the results of the other
servers and a warning. An older server that does not provide a Neighborhood
adds no results.

Servers that are already registered remain in the directory and have a
**Joined** label. A compatible unregistered server has a **Join** action. When
you select **Join**, the client contacts that server to load its current
sign-in options. If
the server version is too old or unknown, use **Open in new tab** to use the
client that the server provides. The server icon opens the same destination.
Use the direct server-address field when the wanted server is not listed. The
same compatibility rule applies to a server found through this field.

## Understand the trust boundary

The Chatto server stores and publishes the origin. A change to a Neighbor does
not contact that server. Neighborhood discovery later reads the public profile
and directory of each Neighbor. It does not verify that:

- the server is compatible;
- the remote administrator approves the listing; or
- the two servers trust each other.

Neighborhood discovery can observe a mutual recommendation when two public
directories advertise each other. It uses this observation only to expand
recursive discovery. Direct recommendations can remain one-sided. Neither case
is authenticated consent, a durable relationship, compatibility, or trust.

Opening the Neighbors administration page makes the client contact advertised
origins. Public discovery and image requests contain no reusable user
credential or referrer data and do not follow redirects. A failed cross-origin
request can still send an unauthenticated CORS preflight. Each remote server
can see your network IP address and technical connection details.

## Use the API

The authenticated `chatto.admin.v1.AdminServerService` provides list, get,
create, update, and delete methods. The public
`chatto.discovery.v1.ServerDiscoveryService.ListNeighbors` method returns
canonical origins without a session. The public
`ListNeighborhoodServers` method returns the cached Neighborhood without a
session. It does not contact other servers. Its logo and banner URLs point to
copies on the called server.

Administrative API callers must send a canonical HTTP or HTTPS origin without
a path, query, fragment, or credentials. The hostname and deep-link input
normalization is a bundled-client feature. Create and update operations return
`FailedPrecondition` when the origin identifies the current server.

An older server can return `Unimplemented` for these public methods. Treat
that result as no available Neighbor directory or Neighborhood.
