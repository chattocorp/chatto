Bots permitem que ferramentas externas publiquem mensagens e respondam a conversas no
Chatto. Crie uma conta de bot, dê acesso às salas necessárias e conecte sua ferramenta
com uma chave de API ou webhook. O software do bot é executado separadamente.

Os passos abaixo configuram um bot que publica atualizações de implantação. Você precisa
de permissão para criar bots e de acesso à sala de destino.

## Escolha como a ferramenta se conecta

Há três métodos de conexão. Um bot pode usar mais de um.

- **Webhook de entrada: sua ferramenta → Chatto.** Dê a um serviço de alertas ou
  ferramenta de automação uma URL para publicar mensagens.
- **Chave de API: seu programa → Chatto.** Dê uma chave ao programa do bot para ler
  mensagens, enviar respostas ou usar outras operações de API permitidas.
- **Webhook de saída: Chatto → sua ferramenta.** Dê ao Chatto um endpoint para avisar
  quando alguém mencionar o bot ou enviar uma mensagem direta. A ferramenta processa
  o evento e usa uma chave de API se precisar responder.

Para atualizações de implantação, use um webhook de entrada. Para um bot que responde
a menções ou mensagens diretas, use um webhook de saída para receber mensagens e uma
chave de API para enviar respostas.

## 1. Crie a conta do bot

1. Abra **Administração do servidor → Bots** no servidor em que o bot trabalhará.
2. Selecione **Criar bot**. Neste exemplo, use `release-bot` como nome de usuário e
   **Atualizações de versões** como nome de exibição. O nome de usuário identifica a
   conta; o nome de exibição aparece ao lado das mensagens para os membros.
3. Crie o bot. O Chatto mostra uma chave de API uma única vez. Salve-a no armazenamento
   de segredos da integração se for usar a API. Não será possível ver essa chave
   novamente depois de fechar o diálogo.
4. Abra a página de detalhes do bot. Dê ao perfil uma descrição curta, como
   “Publica resultados de implantação do nosso processo de lançamento”.

Se **Criar bot** não estiver disponível, peça `bot.create` a um administrador. Ser dono
permite gerenciar esse bot; o direito de gerenciar todos os bots é uma permissão separada.

Se a ferramenta só usa um webhook de entrada, ela não precisa de chave de API. Revogue
a chave inicial não utilizada em **Integrações → Chaves API**.

## 2. Dê acesso a uma sala

Um bot novo não tem permissões. Ele não herda os papéis do dono nem as permissões do
papel `everyone`. Entrar em uma sala e ter permissão para publicar nela são requisitos separados.

1. Abra a aba **Permissões** do bot.
2. Encontre a coluna da sala de atualizações de implantação.
3. Na linha **Inscreveu-se**, no topo da matriz, selecione a sala e confirme a alteração de participação.
4. Permita `message.post` nessa sala. Deixe sem definição as permissões não necessárias.

O bot de implantação não precisa de acesso de leitura. Conceda `message.post` na coluna
da sala para limitar a publicação àquela sala. Uma permissão no nível do servidor vale
para várias salas.

Você também precisa de autoridade para adicionar o bot à sala. Salas arquivadas e
suspensões podem impedir a entrada. A permissão `room.join` do próprio bot serve para
entrar em salas pela API; ela não substitui a linha **Inscreveu-se**.

### Um bot não pode superar o acesso do dono

Cada permissão do bot é limitada pelas permissões atuais do dono humano no mesmo escopo.
Uma permissão salva pode estar inativa: um cadeado na matriz indica que as permissões
do dono a bloqueiam. Se o dono perder acesso, o bot também perde. Sair da conta não para o bot.

Algumas permissões exigem o modo privilegiado. Se o Chatto pedir para ativá-lo, faça isso
antes de adicionar a permissão.

## 3. Conecte um webhook de entrada

1. Abra **Integrações** na página de detalhes do bot.
2. Em **Webhooks de entrada**, selecione **Criar webhook**.
3. Dê o nome do sistema que fará as chamadas, por exemplo **Processo de lançamento**.
4. Selecione a sala de atualizações de implantação como **Sala de destino**.
5. Crie o webhook e copie a URL completa para a configuração da ferramenta.
   Preserve a parte `?room_id=…` da URL.

Configure a ferramenta para enviar um **POST** HTTP com `Content-Type: application/json`
e este corpo:

```json
{
  "text": "Implantação concluída: a versão **0.5** está pronta para testes."
}
```

A sala escolhida já está na URL, então essa solicitação não precisa do campo `channel`.
Se escolher **Escolher em cada solicitação**, inclua `"channel": "YOUR_ROOM_ID"`
no JSON. Use o ID da sala, não o nome.

Escolher um destino adiciona o ID da sala à URL. Quem faz a chamada pode mudar esse ID
e publicar em qualquer sala em que o bot possa publicar. Para restringir o webhook
a uma sala, conceda ao bot permissão de publicação somente nela.

## 4. Envie um teste e confira o resultado

Use a função de teste da ferramenta externa. Uma solicitação de entrada bem-sucedida
retorna HTTP `200` com o texto `ok`. No Chatto, a mensagem deve aparecer na sala escolhida
como **Atualizações de versões**, com o rótulo **BOT** e “0.5” em negrito.

Se a solicitação falhar, confira a resposta:

- **`401 invalid_token`:** a URL está incompleta, é inválida ou foi revogada. Crie um
  novo webhook de entrada se não tiver mais a URL completa.
- **`404 channel_not_found`:** confira o ID da sala, a participação do bot, sua permissão
  `message.post` e o acesso de publicação do dono naquela sala.
- **`400 invalid_payload`:** envie JSON válido com texto de mensagem não vazio e um ID
  de sala. Se o ID aparecer na URL e no corpo, os valores devem ser iguais. As políticas
  da sala e os limites de tamanho das mensagens também se aplicam.
- **A mensagem aparece duas vezes:** uma nova tentativa pode criar outra mensagem.
  Webhooks de entrada não fornecem uma chave de idempotência para eliminar duplicatas.

Depois que o teste funcionar, configure a ferramenta para chamar o webhook ao terminar uma implantação.

## Crie um bot que responde às pessoas

Configure o programa do bot com sua chave de API do Chatto. Guarde a chave na configuração
secreta do programa. As solicitações de API se autenticam com o cabeçalho
`Authorization: Bearer YOUR_API_KEY`.

Escolha as permissões necessárias:

- **Responder somente quando chamado:** conceda `message.read-interactions` e
  `message.post-in-interactions`. O bot pode ler tópicos completos que iniciou, tópicos
  em que alguém o mencionou diretamente e suas mensagens diretas. Mencionar o bot pode,
  portanto, dar acesso também a mensagens anteriores naquele tópico.
- **Ler a sala, mas responder somente quando chamado:** conceda `message.read` e
  `message.post-in-interactions`.
- **Ler todas as mensagens e iniciar conversas:** conceda `message.read` e `message.post`.

Aplique as permissões às salas pretendidas. Para mensagens diretas, use o escopo
**Mensagens diretas** na matriz. As permissões do dono continuam limitando essas concessões.

### Informe ao programa quando responder

Se o programa aceita eventos de webhook do Chatto:

1. Abra **Integrações → Webhooks de saída → Criar webhook**.
2. Informe um nome e o endpoint HTTPS público do programa.
3. Se o receptor exigir um **Cabeçalho de autorização**, informe o valor completo esperado,
   incluindo um prefixo como `Bearer`.
4. Copie o segredo de assinatura para a configuração do receptor se ele verificar as
   assinaturas dos webhooks do Chatto. O segredo é mostrado uma única vez.
5. Mencione o bot em uma sala que ele possa ler ou envie uma mensagem direta. Confira
   os registros do receptor e a resposta do bot no Chatto.

O endpoint recebe mensagens novas que mencionam diretamente o bot ou que são mensagens
diretas dele. Mensagens comuns de sala, edições, reações e mensagens enviadas pelo próprio
bot não acionam esses webhooks. Uma resposta comum posterior em um tópico de sala também
não aciona o webhook, a menos que mencione o bot novamente.

O receptor deve aceitar o evento com uma resposta HTTP 2xx e depois enviar qualquer
resposta ao chat pela API. O Chatto ignora o corpo da resposta HTTP. As entregas podem
se repetir, então o receptor deve usar o ID da entrega para não fazer o mesmo trabalho
duas vezes. Para um programa que precisa de toda a atividade legível, use a API em
tempo real do Chatto em vez do webhook de menções e mensagens diretas.

Para o conteúdo dos eventos, a verificação de assinaturas e as operações da API, consulte
a [referência de webhooks de bots](https://docs.chatto.run/reference/bot-webhooks/)
e a [referência da API](https://docs.chatto.run/reference/connectrpc-api/).

Um webhook de saída envia o texto da mensagem e os identificadores da mensagem, autor,
sala e bot ao endpoint configurado. O receptor também vê o endereço IP de saída do
servidor Chatto. Se o bot encaminha mensagens a um provedor de IA ou outro serviço,
explique isso aos membros antes de usá-lo nas conversas deles.

### Se o bot não responder

Confira se o programa recebeu o evento. No webhook de saída, abra **Falhas recentes**
para ver os erros de entrega registrados. Confira se o endpoint está ativado, acessível,
aceita a autenticação configurada e retorna 2xx sem redirecionamento. Uma lista vazia
de falhas não comprova que a entrega funcionou.

Se o evento chegou mas não apareceu resposta, confira a chave de API do programa,
a operação de resposta e as permissões efetivas de leitura e publicação do bot.

## Mantenha a integração

- **Substituir uma credencial:** crie uma chave ou webhook novo com nome, atualize o
  sistema que o chama, teste e revogue o anterior. Chaves de API não expiram automaticamente.
  Nunca cole uma chave real ou URL com credenciais no chat ou no controle de versão.
- **Parar a entrega de saída temporariamente:** selecione **Pausar** no endpoint.
  **Retomar** permite eventos novos; não reproduz o período pausado.
- **Passar o bot a outro dono:** uma conta com `bot.manage` pode usar **Reatribuir proprietário**.
  O acesso efetivo do bot passa imediatamente a seguir o novo dono. As chaves existentes
  continuam válidas; troque as credenciais se o operador anterior tiver que perder acesso.
- **Remover uma conta proprietária:** reatribua primeiro os bots de longa duração.
  Excluir um dono humano também exclui os bots dele.
- **Mostrar aos membros o que o bot pode fazer:** abra o perfil e consulte **Proprietário**
  e **O que ele pode fazer**. Revise esse acesso depois de mudar as salas ou a propriedade.
