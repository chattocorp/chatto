## AdminUserService

Server-admin user management commands and member-detail reads.

<a id="chatto-admin-v1-AdminUserService-ListUsers"></a>

### ListUsers

Lists administrative user IDs. Requires admin.view-users.

```http
POST /api/connect/chatto.admin.v1.AdminUserService/ListUsers
```

<a id="chatto-admin-v1-ListUsersRequest"></a>

#### Input: ListUsersRequest

Request administrative user IDs in creation order, oldest first. Accounts
without a creation time follow, ordered by case-insensitive login. IDs break ties.

| Field | Type | Description |
| --- | --- | --- |
| `search` | `string` | Case-insensitive login/display-name search. Empty selects all accounts. |
| `page` | [`chatto.api.v1.PageRequest`](/reference/connectrpc-api/types/#chatto-api-v1-PageRequest) | Default limit 20; maximum 100. Offsets count IDs, not hydrated records. |


<a id="chatto-admin-v1-ListUsersResponse"></a>

#### Result: ListUsersResponse

One live page of user IDs. Changes between requests can shift offsets.
Hydrate with BatchGetUsers and advance by the number of returned IDs.

| Field | Type | Description |
| --- | --- | --- |
| `user_ids` | `repeated string` | Matching IDs in list order. |
| `page` | [`chatto.api.v1.PageInfo`](/reference/connectrpc-api/types/#chatto-api-v1-PageInfo) | Count and continuation information for the selected accounts. |

### BatchGetUsers

Gets administrative accounts in first-seen request order. Requires
admin.view-users. Unknown or deleted users are omitted; repeated IDs are
returned once. The whole request fails if access or account hydration fails.

```http
POST /api/connect/chatto.admin.v1.AdminUserService/BatchGetUsers
```

<a id="chatto-admin-v1-BatchGetUsersRequest"></a>

#### Input: BatchGetUsersRequest

Request administrative accounts for a bounded set of IDs.

| Field | Type | Description |
| --- | --- | --- |
| `user_ids` | `repeated string` | Unknown or deleted users are omitted. Repeated IDs are returned once. |


<a id="chatto-admin-v1-BatchGetUsersResponse"></a>

<a id="chatto-admin-v1-AdminUserService-SetUserDeactivated"></a>

### SetUserDeactivated

Deactivates or reactivates a human account. Requires user.manage-accounts.
The caller cannot target their own account or an owner account.
Deactivation immediately invalidates existing sessions and prevents sign-in.
Reactivation permits new sign-ins; old sessions remain invalid.
Repeating the current state succeeds without changing it.

```http
POST /api/connect/chatto.admin.v1.AdminUserService/SetUserDeactivated
```

<a id="chatto-admin-v1-SetUserDeactivatedRequest"></a>

#### Input: SetUserDeactivatedRequest

Set account access without deleting user data.

| Field | Type | Description |
| --- | --- | --- |
| `user_id` | `string` | No field description provided. |
| `deactivated` | `bool` | No field description provided. |
