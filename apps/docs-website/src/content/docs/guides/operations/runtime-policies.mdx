---
title: Runtime Policies
description: Configure inherited server, room-group, and room behaviour while Chatto is running.
---

Runtime policies are typed settings that change community behaviour without a
server restart. They are separate from permissions: a permission decides who
may perform an action, while a policy controls how an allowed feature behaves.

## Inheritance

Each policy resolves independently in this order:

1. room override
2. the room's current room-group override
3. server override
4. Chatto's product default

Only explicit overrides are stored. Choose **Inherit** at any level to clear
that override and use the next value in the chain. Parent values are defaults,
not limits: a room can select any value allowed by the policy even when its
group or server uses another value.

Moving a room to another group immediately changes the group value it inherits.
Direct messages have no group or room policy overrides and inherit from the
server.

## Configure Policies

Open **Server Admin → Policies** to set server-wide defaults. The same Policies
panel appears on a room group's and a room's management page for administrators
with `room.manage` there.

The panel shows both the override stored at the current scope and the effective
value with its source. Changes save immediately and are recorded as durable
events, so they are included in normal EVT backups and the administrative event
log.

## Author Edit Window

The first runtime policy controls how long authors may edit their own messages:

- The product default is 3 hours.
- Available administration presets range from Disabled through 7 days; the API
  accepts typed values from 0 seconds through 30 days.
- Disabled means authors cannot edit after posting.
- Users with `message.manage` can still edit messages without a time limit.
- The server evaluates the current effective value when an edit commits.
  Lowering the window can immediately close existing messages; raising it can
  make them editable again.

Connected policy-aware clients receive updated room state through the realtime
projection. During a mixed-version deployment, an older client may briefly show
an edit action based on the server-wide value, but authoritative server
enforcement still applies.

## API

Integrations can read sparse overrides and update selected fields with
`chatto.admin.v1.AdminPolicyService`. The update field mask preserves
unselected overrides; omitting the value for a selected field clears that
override. Normal clients receive effective policy values in
`chatto.api.v1.RoomViewerState`; they do not need to reproduce the inheritance
algorithm.
