Members can upload files, images, avatars, and server branding images. Chatto
also stores link-preview images and, when you enable it, processes videos and
animated GIFs. By default, Chatto keeps these assets in NATS. For many or large
files, use S3-compatible storage.

## What Members Can Upload

| Asset type | Behavior |
| ---------- | -------- |
| Images | Chatto serves resized WebP versions on request. Set `core.assets.cache.enabled = true` to cache them. |
| Documents and other files | Chatto serves them through signed URLs. |
| Videos | Chatto accepts them only when `video.enabled = true`. |
| Animated GIFs | Chatto stores them as images. When video uploads are enabled, it also converts them to video. |
| Avatars, logos, banners | Profile and administrator permissions control them. |
| Link-preview images | Chatto downloads, limits, and stores them in the asset storage. |

| Limit | Default | Setting |
| ----- | ------- | ------- |
| Images and other files | 25 MB | `core.assets.max_upload_size` |
| Videos | 100 MB | `video.max_upload_size` |

Browsers upload message attachments in chunks of up to 10 MiB. If your reverse
proxy limits the request body size, allow at least 11 MiB for each request.
Avatar and branding uploads can need larger request bodies.

## Attachment Descriptions

Members add a description in the attachment preview before they send a
message. After they send it, they can add, replace, or remove it in the
attachment controls. A description can have line breaks and up to 1,000
characters.

Chatto uses the description as alt text for images, and the filename when no
description exists. The image viewer also shows it as a caption. Video, audio,
and file controls give it to assistive technology.

Chatto encrypts each description with the content key of the message author.
Description changes use the same three-hour window and `message.manage`
override as message-text edits.

## Permission And Access Model

To attach a file, a member needs:

- room membership
- `message.post`, `message.post-in-thread`, or `message.post-in-interactions`,
  and read access for thread replies
- `message.attach`

Attachment URLs are signed for one user and expire. Each request also checks
that this user can still read the room. When a member leaves the room or loses
access, old URLs stop working for them.

## Room Files

The **Files** panel in the room sidebar lists the attachments of visible
messages and thread replies. A file disappears from the list when its message
or attachment is deleted. The panel has no search or filter.

## Link Previews

When a member writes a message with a URL, the Chatto server fetches the page
metadata and preview image. The linked site sees the server's IP address, not
the member's. The fetcher blocks private network addresses and caches results
for a limited time. You do not need a separate worker.

Public Bluesky and Mastodon posts show as native cards with the author, text,
images, and one quoted post. Mastodon content warnings stay closed until the
reader opens them. Chatto supports all compatible public Mastodon servers.
Clients show the stored card and do not contact the provider. When Chatto
cannot read the post, it shows a normal link preview.

## Storage Backend Choice

| Deployment | Storage |
| ---------- | ------- |
| Small server, few uploads, a few GB in total | NATS (default) |
| Active community with many files or videos | S3-compatible storage |
| Replicated NATS cluster | S3-compatible storage, so that NATS does not copy large files to each node |
| Existing S3 or CDN infrastructure | S3-compatible storage |

Each asset records its storage backend. When you change the backend, new
assets go to the new backend, and existing assets stay readable. Asset URLs do
not change.

## S3 Storage

<Tabs>
<TabItem label="TOML">

```toml
[core.assets]
storage_backend = "s3"

[core.assets.s3]
endpoint = "s3.amazonaws.com"
bucket = "chatto-assets"
path_prefix = "production/chatto"
region = "eu-central-1"
access_key_id = "<generate-me>"
secret_access_key = "<generate-me>"
```

</TabItem>
<TabItem label="Environment">

```bash
CHATTO_CORE_ASSETS_STORAGE_BACKEND=s3
CHATTO_CORE_ASSETS_S3_ENDPOINT=s3.amazonaws.com
CHATTO_CORE_ASSETS_S3_BUCKET=chatto-assets
CHATTO_CORE_ASSETS_S3_PATH_PREFIX=production/chatto
CHATTO_CORE_ASSETS_S3_REGION=eu-central-1
CHATTO_CORE_ASSETS_S3_ACCESS_KEY_ID=<generate-me>
CHATTO_CORE_ASSETS_S3_SECRET_ACCESS_KEY=<generate-me>
```

</TabItem>
</Tabs>

Chatto creates the bucket at startup if it does not exist.

| Setting (`core.assets.s3.*`) | Default | Description |
| ------- | ------- | ----------- |
| `endpoint` | — | S3 endpoint host |
| `bucket` | — | Bucket name |
| `path_prefix` | — | Optional key prefix for all objects |
| `region` | — | Region. Optional for services other than AWS. |
| `access_key_id`, `secret_access_key` | — | Credentials |
| `use_ssl` | `true` | Use HTTPS to connect to S3 |
| `path_style` | `auto` | URL addressing. `auto` uses virtual-hosted URLs for AWS and path-style URLs for other endpoints. |

Any service with the S3 API works. Examples of endpoints:

| Provider | `endpoint` | `region` |
| -------- | ---------- | -------- |
| Cloudflare R2 | `<account-id>.r2.cloudflarestorage.com` | — |
| Wasabi | `s3.eu-central-1.wasabisys.com` | `eu-central-1` |
| Backblaze B2 | `s3.us-west-004.backblazeb2.com` | `us-west-004` |

### Change the storage configuration

- To go back to NATS, set `storage_backend = "nats"`. Files in S3 stay
  readable.
- To change `path_prefix`, first move or copy the objects to the new prefix.
  Chatto stores keys without the prefix, so it needs no other change.

<Aside type="caution">
  Chatto has one S3 configuration. If you change the endpoint or the bucket,
  Chatto cannot read files in the old location. To move to a different
  provider or bucket, copy all objects first.
</Aside>

`chatto backup` does not include S3 objects. Back them up with your storage
provider. See [Backup & Restore](/guides/operations/backup-restore/).

## Video Processing

Video uploads are off by default. When you enable them, a worker makes a
thumbnail and adaptive HLS renditions for each video and animated GIF. The
worker needs `ffmpeg` and `ffprobe`. The official Docker image includes them.
For other installations, install the `ffmpeg` package.

<Tabs>
<TabItem label="TOML">

```toml
[video]
enabled = true

[asset_processing]
enabled = true
max_concurrent_jobs = 2
```

</TabItem>
<TabItem label="Environment">

```bash
CHATTO_VIDEO_ENABLED=true
CHATTO_ASSET_PROCESSING_ENABLED=true
CHATTO_ASSET_PROCESSING_MAX_CONCURRENT_JOBS=2
```

</TabItem>
</Tabs>

`video.enabled` accepts video uploads and queues their processing.
`asset_processing.enabled` starts the worker inside `chatto run`.

<Aside type="caution">
  `asset_processing.enabled` is `false` in existing configuration files.
  `chatto init` writes `true`. If no worker runs, new videos stay in
  processing.
</Aside>

| Setting | Default | Description |
| ------- | ------- | ----------- |
| `video.enabled` | `false` | Accept video uploads and queue processing |
| `video.max_upload_size` | `100 MB` | Maximum video file size |
| `asset_processing.enabled` | `false` | Start the worker inside `chatto run` |
| `asset_processing.ffmpeg_path` | from `PATH` | Path to `ffmpeg` |
| `asset_processing.ffprobe_path` | from `PATH` | Path to `ffprobe` |
| `asset_processing.max_concurrent_jobs` | `2` | Parallel jobs in each worker process |
| `asset_processing.temp_dir` | system temp | Directory for temporary files |

### Run workers separately

Transcoding uses much CPU. To keep this work away from the server processes,
disable the built-in worker:

```toml
[video]
enabled = true

[asset_processing]
enabled = false
max_concurrent_jobs = 4
```

Then start one or more workers with the same configuration:

```bash
chatto asset-processing --config chatto.toml
```

This command always runs the worker, independently of
`asset_processing.enabled`. The worker must reach the same NATS server and
asset storage. Set `nats.client.url`. If Chatto uses embedded NATS, expose its
client port to the trusted network only.

Workers share one queue. Each job goes to one worker. If a worker stops during
a job, another worker does the job again. While no worker runs, members can
still send messages, and their videos stay in processing.

### Processing behavior

1. Chatto stores the original upload immediately.
2. The message shows the video as processing.
3. A worker makes a thumbnail and six-second HLS segments. It converts audio to
   AAC stereo.
4. The player starts adaptive playback. Seeking works with NATS and S3
   storage.

A job can use 30 minutes. After that, Chatto records a failure and does not
try again. If processing fails, for example with an unsupported codec, the
member sees an error and can upload again. Videos from older Chatto versions
keep their MP4 files.

Chatto stores the original, the thumbnail, and the HLS segments. Put
`asset_processing.temp_dir` on fast disk with space for the jobs that run at
the same time.

## HTML Attachments

Select an HTML or XHTML attachment to open its viewer. The viewer shows the
document type and file size. **Download** saves the original file and does not
load the preview.

**Show preview** loads the document. Before this, Chatto loads nothing from the
document. A notice tells the member that external websites can see their IP
address if the document loads content from them. The member must make this
choice each time.

The preview blocks scripts, forms, popups, and access to Chatto. Documents that
need scripts can fail. **Download** and **Close** stay available outside the
preview.

API clients can add `download=1` to the original attachment URL. Keep the
`access` parameter. Chatto then returns the original file as a download, also
for S3 storage.

## Active Document Safety

Chatto serves uploaded HTML, XHTML, SVG, XML, and related formats with a
sandbox policy, `nosniff`, and `Referrer-Policy: no-referrer`. With S3 storage,
Chatto streams these files itself and does not redirect to S3. This keeps the
sandbox headers in place.

See [Environment Variables](/reference/environment-variables/#assets) for all
asset settings.
